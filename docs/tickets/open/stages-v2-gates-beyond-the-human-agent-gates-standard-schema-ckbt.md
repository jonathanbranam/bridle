## Outcome

Gates are not only the human's, tickets can take standard schemas, and the rules reach the build.

## Scope

- "Approve with feedback": the writer fixes the comments and the stage moves on without a second
  review (the human: "I just want to change these three things, and then it's fine. I don't want to
  see it again").
- Gates signed by agents (other kinds of review), and consulted reviewers who comment without
  signing (RACI words in the docs only; "let's not use RACI terms in the schema").
- Standard schemas assigned to a ticket, and stage types beyond the four (the human: "every ticket
  could have different stages in the future: different gates, different steps").
- Attachments of any type, images first.
- Spec re-review: if the merged specs differ from the reviewed specs.md and the specs stage had a
  review gate, the new specs go back to that reviewer ("TBD if that is only an inform or an
  approval").
- Rules injected into the apply step at the moment of work ("really helpful for certain very tight
  programming things where we want the code written in a specific way").
- Rework mhjn (who readies what) around "ready means prepared".
