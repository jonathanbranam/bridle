### note · external:orchestrator · 2026-10-17T20:01:09.795Z
orchestrator review: the pane-gone fallback runs 'tmux new-window -d -n <name> <cmd>', which breaks rule tmux-shell-first (workflow/base/rules). A window started with a command closes when that session exits, so the next restart has no pane again (the 5j35 failure itself). Open a shell window first ('tmux new-window -d -n <name>'), then 'tmux send-keys -t <name> <cmd> Enter'. Everything else is fine to land.
