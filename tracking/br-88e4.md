Seen on remus, bridle 0.8.0, 2026-11-17 ~04:15 UTC, right after a clean `bridle token pair` (human-run from remus-home; no failed lines: dalek minted 26/kept 34, remus 10/52, vesta 15/45).

`bridle projects setup <p> --check` still prints, for flume (new tonight), glassbox and remus-home alike:
  tokens ... todo: tokens missing on some machine
  aide token ... todo: tokens missing on some machine
  next: bridle token pair --projects flume
glassbox and remus-home have run for weeks with working aide, advisor and orchestrator tokens, and flume's aide and advisor started fine and its mail forwards to remus-home. So the check is wrong, or it names a missing token without saying which one or where.

A possible lead: an earlier pair run printed check lines like "check remus peer -> remus/glassbox: refused: daemon: error: forbidden: this endpoint is human-only" and "check remus orchestrator -> remus/flume: refused: error: no entry". If the setup check counts a human-only refusal as missing, that would explain it.

Ask: the check passes when the tokens work; when it does report missing, it names the principal, project and machine. Following its "next:" advice (token pair) must clear it.
