Design (the spec): docs/design/agent-host/orchestrator-supervision.md, sections 1-4, 8 and the build-slice list in 9 (read all of it) plus docs/spikes/07-orchestrator-supervision-findings.md (verified tmux/pid/hook behaviour; cite it). This is the first half of design slice 1; the wake command and wake conditions (section 5) are the NEXT task, out of scope here. Build: 1) crates/bridle-daemon/src/orchestrator.rs (new): a supervisor task ticking every 10 s: pid-file liveness (pid plus process start time must match, reuse the containment/ps helpers agents use), find the pane by tmux tag @bridle=orchestrator only when a relaunch is due, safe-to-type check (session dead AND pane_current_command a shell on two checks 5 s apart), relaunch by tmux send-keys -l of the absolute launcher path then a separate Enter, confirmation within 60 s (pid file changes to a live pid), crash-loop backoff per relaunch_backoff and stable_after, give up after the last backoff until a live pid appears, no pid file means do nothing and log once. tmux behind a trait so tests fake it. 2) The interim 'record an incident' function from section 8: one function that sends a system message to human and appends an orchestrator.incident event (nc7r will replace it); no new incident store. 3) crates/bridle-daemon/src/config.rs: [orchestrator] table with enabled (default false), launcher, relaunch_backoff, stable_after (waiter_grace can wait for the next task); validation and tests; wiring where the daemon starts its other background loops. 4) crates/bridle/src/cli.rs and commands.rs: bridle orchestrator note-session (reads the SessionStart hook JSON on stdin, writes $BRIDLE_HOME/orchestrator.session as '<session id> <transcript path>'; must never fail loudly). 5) scripts/claude-orchestrator: write the pid file '<pid> <process start time> <launch epoch>' just before exec claude, pass --settings with the SessionStart hook for this session only, stop pinning --session-id and writing ~/.bridle-orchestrator-session (check scripts and docs/context for other readers of that file first and keep them working until the next task). Do NOT run the launcher against the live orchestrator or type into any real tmux pane in tests; use fakes and a scratch tmux server (tmux -L scratch) at most. Docs: update the design file's status, daemon.md loops, cli.md, roles-and-config.md and CHANGELOG. Acceptance: just check passes; unit tests with fake tmux and fake clock for alive/dead, backoff sequence, give-up, stable reset, unsafe pane (non-shell foreground), no tagged pane (incident, retry). Model: Sonnet. Out of scope: wake conditions, wait-for-wake, context/uptime thresholds, handover records, deleting orchestrator-watch.sh.
