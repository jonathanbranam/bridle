GOAL: revise docs/design/agent-host/incidents.md to the human's decision (2026-09-29/30, verbatim in tickets nc7r and ex9q on main; read the 'human's decision' section of nc7r and the current incidents.md, docs/design/coordination.md and storage.md for the task state machine). New design: NO incidents table and no new record type. An incident is a task of kind 'incident', owned by the orchestrator, with the usual body and thread (comments, updates). States: potential -> active -> resolved (the orchestrator promotes a potential one to active, or drops it, and resolves it). Anyone may file a potential incident, after searching open incidents (bridle task search/list). The ONLY new machinery: a persistent notice broadcast to every agent while an incident is active, including agents that start, resume or renew; on resolve, agents that saw it get a short 'resolved'; an undelivered notice is dropped, never delivered late (keep that behaviour from the old design, via the message queue's pending/held handling). Decide and write down, simply: how the kind maps onto the existing task states (reuse open/planned/done/dropped where possible rather than adding states; KISS), which surfaces exist (bridle task new -k incident, status lists active incidents, events), and the audience (all agents; role-scoped only if trivial). Docs only: edit incidents.md, and fix references in cli.md, coordination.md, storage.md, docs/README.md if they mention the old table or commands. Add a CHANGELOG line. Acceptance: just check passes. Model: Sonnet. Out of scope: any code (next task builds it).
