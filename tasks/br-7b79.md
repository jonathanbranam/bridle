Ticket: docs/tickets/open/restart-on-linux-execs-path-deleted-after-the-binary-is-repl-fpde.md (read it). The imported record is br-e851; this task is the build. URGENT: the NUC runs unattended until Fri late, so this must land today; keep it narrow.

Bug: on Linux std::env::current_exe() reads /proc/self/exe, which names "<path> (deleted)" once cargo install replaces the file; exec_self and roll_back (crates/bridle-daemon/src/lib.rs ~:216, ~:230) then exec that literal path, fail with ENOENT and the daemon exits. upgrade.rs (~:167 rollback stash, ~:187 the `serve --check` preflight) calls current_exe() too, so self-upgrade breaks the same way.

Do, and ONLY this:
1. One helper (e.g. exe_path()) that resolves the binary path ONCE at daemon start-up (store it in a OnceLock or the daemon state, set before anything can replace the file) and strips a trailing " (deleted)" as the fallback. Use it for every re-exec, the preflight and the rollback stash/exec: replace each current_exe() call on those paths.
2. If the exec still fails, the daemon STAYS UP and reports the error (tracing error plus whatever existing report channel restart uses, e.g. the restart response or an incident as the code already does for failed restarts); never exit on a failed exec. Keep the existing rollback/pre-flight logic as is.
3. Tests: unit test for the suffix handling (with and without the suffix, a path that contains the substring elsewhere is untouched); a test that a failed exec leaves the process running (use an injectable exec fn if one exists, or a nonexistent path through the helper's fallible layer). A Linux-only test that replaces a copied binary and checks the resolved path is welcome if cheap (#[cfg(target_os = "linux")]); the project is developed on macOS so do not make macOS CI depend on it.
Docs: one line in the restart/upgrade design doc (docs/design/agent-host/daemon.md or wherever restart is described), CHANGELOG entry.
Acceptance: just check passes. Model: Sonnet. May land normally.
Out of scope: ANY other change on the restart or upgrade path (ordering, timing, flags, release self-upgrade br-88d4), the daemon's start-up otherwise.
