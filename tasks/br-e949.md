Design (the spec): docs/design/agent-host/orchestrator-supervision.md section 5 and the slice-1 file list in 9; 1a (the supervisor, config, incident function, launcher changes) has landed before you start: read orchestrator.rs first. Build: move the wake conditions of scripts/orchestrator-watch.sh into the daemon per the section 5 table (agent exited/crashed/stalled from the event log, unreported question to the human, message to the orchestrator by seq cursor, all agents idle 15 min, five_hour >= 93% or seven_day >= 85%, budget hold begins, failed CI run on main from the [ci] watcher records, main moved). Each fires once keyed by what it saw; wakes queue, never drop; cursors are the daemon's own with the wake cursor as a single store row (store.rs, schema version bump, storage.md). GET /v1/orchestrator/wake long poll (server.rs, bridle-api types and client), answering with reasons as JSON, marking them delivered, empty after 5 min; 403 for principals other than external:orchestrator. bridle wait-for-wake command prints the reasons and exits 0 ('nothing' when empty). Waiter tracking: session alive and no open wake request for longer than waiter_grace (config, default 2m) records one incident through 1a's function, closed when a request arrives. Then delete scripts/orchestrator-watch.sh and the ~/.bridle-orchestrator-{seen-questions,hold-state,ci-seen,ctx-level} readers, and change workflow/base/roles/orchestrator.md's watcher step to: run bridle wait-for-wake in the background, on exit read what it printed, act, run it again (scripts/context-check.sh stays until slice 2). Docs: api.md, cli.md, storage.md, daemon.md, the design file status, CHANGELOG. Acceptance: just check passes; tests per condition (fires once, queued while nobody waits, returns at once on the next poll), 403, waiter incident. Model: Sonnet. Out of scope: context/uptime thresholds and forced restart (slice 2), handover records (slice 3). If this proves over ~200K of context to build, split off the CI/hold/usage conditions and say so in a note.
