Goal: an agent that isn't bridle-hosted (the orchestrator, the advisor) or a worker running it as a background Bash can wait for a task state change or a new message instead of polling. Design: docs/design/cli.md ('bridle wait <id> [--until <state>] [--or-message] [--timeout]'), roles-and-lifecycle.md (line ~107: run as background Bash, the caller is woken), coordination.md (the hook table). Read docs/design/agent-host for the SSE event stream the CLI already uses (bridle events, the TUI) and reuse it, no polling loop if the stream can do it. Do: bridle wait <task> --until <state> (default: any state change), --or-message (also return when the caller's inbox gets a message), --timeout <secs> (exit code distinct from success), prints one line saying what happened, exit 0 on the condition, and --json as elsewhere. Add the daemon side only if the event stream lacks task state events; if it does, add them with the wire change in crates/bridle-api/src/types.rs, daemon and clients together. Update docs/design/cli.md (mark built) and the role prompts under workflow/base/ only where they already mention wait. Acceptance: just check passes; tests: returns on a state change, returns on a message with --or-message, times out with the timeout exit code, returns at once when the task is already in the state. Model: Sonnet. Out of scope: prime for other roles, wait on agents.
