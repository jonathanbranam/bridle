Ticket: docs/tickets/open/track-the-human-s-time-and-attention-spent-talking-to-agents-u6w9.md (read it). Original task br-d772 is the imported ticket record; this task is the build.

Goal: start collecting, today, when the human types a prompt into an interactive bridle session. COLLECTION ONLY: no reports, no CLI/daemon changes.

Design (KISS, no daemon): the UserPromptSubmit hook `bridle focus gate` (crates/bridle/src/focus.rs, hook wired in crates/bridle/src/session.rs:22, subcommand in cli.rs:1532) runs on every prompt the human types in the orchestrator and advisor sessions. Make it append ONE JSON line to `<bridle_home>/prompts.jsonl` (discovery::bridle_home(): $BRIDLE_HOME else ~/.bridle): {"at": RFC3339 UTC, "session": <session id from the hook's stdin JSON if present>, "role": <orchestrator|advisor|advisor-<name>, from the session environment the launcher sets, or null>, "machine": <hostname, the same one k7mw uses for machine names if there is a helper>, "project": <repo/workspace name or null>}. NEVER record the prompt text or anything else from the stdin JSON. One write call with O_APPEND of a single short line, so concurrent sessions do not interleave.
Record on EVERY prompt, including when [[focus]] is not configured or no window is active (so do it before the gate's early returns), but only from the interactive session hook (the gate is only installed there).
HARD CONSTRAINTS (trip-safe; the human is away): it must FAIL OPEN. Any error (missing dir, read-only home, bad stdin, clock problem) is swallowed (tracing::debug at most): the hook still exits 0 and prints exactly the gate output it printed before. The gate output must be byte-identical to today in every case (existing focus tests stay green unmodified). Do not touch the daemon or its start-up path. No new dependency unless already in the workspace. Do not block on stdin if it is a tty or absent.
Tests: a line is appended with the right fields and no prompt text; two calls append two lines; an unwritable/missing home does not change the gate output or exit status; existing gate tests unchanged. Docs: a short paragraph in docs/design/agent-host/roles-and-config.md (or the focus section) naming the file and its fields, and that reports are a later task (ticket u6w9); CHANGELOG entry.
Acceptance: just check passes. Model: Haiku.
Out of scope: reports, aggregating across machines, tracking CLI calls, session start/stop events, rotation of the file (note its growth rate in the docs: one short line per prompt).
