Part of onboarding data-contracts (docs/context/onboarding-data-contracts.md §3, §7 step 2;
go-ahead from the orchestrator/human 2026-09-28). data-contracts is the first Python
project bridle onboards; it needs an L2 pack (docs/design/workflow-layers.md) for the
Python-specific rules the survey classified "Py".

Brief: create workflow/packs/python/ following the same layer shape as workflow/base/
(rules/<id>.md, one must/should statement per file, with ids -- see workflow/base/rules/
for the existing pattern and id conventions). Cover, from the survey's §3 table:
- uv as the package manager / `uv run pytest` as the test runner.
- ruff for both lint (`ruff check .`) and format (`ruff format .`).
- "Test at the supported Python floor" (the pack states the rule; the floor value itself,
  e.g. 3.12, is a per-project setting data-contracts supplies in its own .bridle/ layer --
  don't hardcode data-contracts' floor into the pack).
- `ruff extend-exclude = ["*.md"]` (or the pack's equivalent guidance) so quoted code
  in prose docs isn't reformatted -- see data-contracts' pyproject.toml and tickets at7m/yhgu
  for why this matters.

This task depends on br-4221 (check-command binding) landing first: the pack's own
"how to run check" rule should point at the binding mechanism br-4221 builds, not
hardcode `make check` or duplicate the just-check logic.

A project opts in via `.bridle/config.toml`'s `packs = ["python"]` (see
docs/design/workflow-layers.md's example). Don't wire data-contracts' own config in this
task -- that happens on data-contracts' side once the pack exists.

Acceptance: just check passes; `bridle rules explain`/`diff` (crates/bridle/src/cli.rs,
commands.rs) picks up the new pack rules when a fixture project lists `packs = ["python"]`
-- add or extend a test fixture if the existing rules tests don't already cover a
non-empty pack.

Out of scope: a TypeScript or other pack; data-contracts' own project-layer config;
anything OpenSpec/spec-pipeline-related (that's P3, not this pack).

Model: Sonnet (new pack content plus a fixture/test).
