Goal: ids like {#r-7fa2} and {#s-b310} written into spec files, unique and never reused. Design: docs/design/specs.md ('Stable ids'). Builds on the bridle-spec parser (br-ae60, must have merged). Do: bridle spec id [paths...] (same path defaults as bridle spec check; local, no daemon) finds requirements and scenarios lacking an id and writes one into the heading, editing the file in place and leaving everything else byte-for-byte identical (do the edit by line, not by re-rendering the AST). Id form: r- or s- plus 4 lowercase hex chars, longer only on collision; unique across the whole spec set being processed AND never reused: keep a committed ledger file (design/specs/.ids, one id per line, appended, sorted or not; document it) of every id ever assigned, so a deleted requirement's id is not handed out again; ids already in files but missing from the ledger are added to it. Idempotent: a second run changes nothing. --dry-run prints what would change. Update docs/design/cli.md and specs.md. Acceptance: just check passes; tests for assignment, byte-for-byte preservation elsewhere, idempotence, no reuse after deletion, collision handling with a seeded generator, dry-run. Model: Sonnet. Out of scope: trace hashes, protected markers, import.
