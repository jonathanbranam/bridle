Ticket: docs/tickets/open/task-watchers-a-creator-field-a-watchers-list-and-wakes-that-xxxq.md, esp. the advisor's correction (2026515) and the human's decision (2026-10-03): task-change notifications are MESSAGES, one line per change, their own message kind; a wake is only the doorbell for interactive sessions; the bookmark is the messages' read state (replaces the persistent wake cursor, br-a34f dropped). Depends on br-ee78 (agents' messages are read automatically on receipt) and br-eb50 (watchers list; use its 'who is notified' function). Code: crates/bridle-daemon/src/principal_wake.rs (task_reasons, TASK_EVENTS, the 1,000,000-event scan), the message store (docs/design/agent-host/messages.md), event emission for task changes, PrincipalWakeReason in bridle-api types.rs.
Goal: when a task changes (TASK_EVENTS: note added, question asked/answered, priority, kind, state), the daemon writes ONE message per watcher (never to the actor who made the change), new kind (e.g. task_update), one line stating what changed: task id and title, who did it, and the change ('planned -> claimed'; 'comment by human: <first 200 chars>'; 'question asked by worker-3: <text>'; priority or kind old -> new). Read the data from the event payload (add fields to it only if needed, backward compatibly). Each change is its own line/message (no de-duplication that hides different changes); coalescing means one message per change, not per task. An unread message already rings the wake, so a watcher is woken by the doorbell and gets the text through the read-on-receipt path from br-ee78. Delete task_reasons, the 'created or claimed' rule and the 1M-event scan. Messages are written in the same transaction/step as the event where practical so none are lost across a daemon restart. Tests: one per change kind; actor not notified; non-watchers not notified; many changes = many messages; unwatch stops them; no loss across a store reopen; old task wake reasons no longer emitted; message wakes still work. Add the new kind wherever message kinds are listed (types.rs, api.md, messages.md; check old clients tolerate an unknown kind). Update role text that tells agents to read the event log after a wake. Docs + CHANGELOG. Acceptance: just check passes. Model: Sonnet. Migration: none (new message kind; existing watchers from br-eb50). Out of scope: the human as watcher (9nrt), the message-delivery-system question (fbfy).
