Bug in br-2e6e (v3dk slice A). 'bridle ticket check' fails on main when a ticket's task body is rewritten: e.g. ticket jb4e 'tasks names br-6d49, which is not a task made from a ticket', because 'ticket new' links the task by a first body line 'original id: <ticket>' (TASK_ORIGIN_PREFIX in crates/bridle/src/ticket.rs) and 'bridle task edit --body' (used to write the brief) dropped it. Any briefed ticket-born task breaks the check.

Goal: the link survives body edits. Simplest fix: when 'task edit --body' (daemon side, or the CLI before sending) is given a body whose first line is not 'original id: ...' and the old body's first line is, keep that line as the first line of the new body. A body that carries its own 'original id:' line wins. Do not add a new structured field (YAGNI). Also make 'ticket check' name the cause in its message ('task body lost its original id line') so the next person can fix it fast.
Tests: edit of a ticket-born task body keeps the first line; an explicit new original-id line is respected; a task with no origin line is unaffected; ticket check is green after a body edit and its error message names the cause for a task that lost it.
Docs: cli.md or task docs where 'task edit' is described, CHANGELOG. Acceptance: just check passes. Model: Sonnet.
Migration plan: none for the code. The PM has already restored the line on br-6d49; the worker should run 'bridle ticket check' on main and fix any other task still missing it (br-2e6e's body, v3dk, is one) by re-adding the first line.
Out of scope: structured link fields. Lands normally once main is green (it was red on a flaky macOS test, m-3243).
