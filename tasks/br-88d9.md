Context: br-a4a6 landed 'bridle agent wake <identifier>' with ONE reason (an unread message) in the daemon's single wake_reasons function (crates/bridle-daemon, see crates/bridle/src/commands/agent.rs and docs/design/agent-host/api.md). The human's decision 2 in docs/tickets/open/interactive-sessions-context-for-all-daemon-decided-wakes-re-jttf.md lists: a comment on or state change of a task the agent should know about.
Goal: add exactly one more reason to wake_reasons: since the caller's last wake (or call start), a task the principal CREATED or CLAIMED had a comment, an ask/answer, a priority/kind change or a state change by someone else (not the principal itself). Return it as a reason 'task' with the task id and event kind, alongside message ids; several reasons can come back together. Use the existing events/thread data; no new table; no subscription config (YAGNI: 'created or claimed' is the whole rule for now, and the rule lives in that one function).
Tests: comment by another principal wakes it; its own comment doesn't; a task it neither created nor claimed doesn't; state change wakes; reasons combine with a message.
Docs: cli.md, api.md, CHANGELOG. Acceptance: just check passes. Model: Sonnet.
Migration plan: none (daemon behaviour; no project files).
SAFETY: only the new agent-wake route; do not touch orchestrator wait-for-wake, start-up or supervision; lands normally. Out of scope: schedules, ticket comments, per-principal subscriptions.
