Goal: a local command that validates specs with the bridle-spec parser (br-ae60, must have merged; read its public API). Design: docs/design/specs.md, specs-to-tests.md, cli.md. Do: bridle spec check [paths...] (default: design/specs/ under the project root, found the way bridle rules does; also accept a --root override so data-contracts can point at openspec/specs during its interim), no daemon call, like bridle rules/sync. Prints each diagnostic as file:line:col: message, then a one-line summary; exit non-zero on any error; --json prints the diagnostics as structured output. Warn (not error) on requirements missing an id, so unmigrated specs can be checked before ids are assigned; a flag --require-ids makes that an error. Add the command to the CLI docs (docs/design/cli.md, marked built) and the design doc. Acceptance: just check passes; CLI tests with a good spec, a bad spec (several diagnostics), missing ids warning vs --require-ids, and --json. Model: Sonnet. Out of scope: id assignment (P3-3), export, import. Can run beside P3-3 and P3-4 but each edits cli.rs; expect trivial conflicts.
