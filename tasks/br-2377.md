Slice B of k7mw (br-36c7; design in docs/tickets/open/projects-on-other-machines-by-config-k7mw.md, section 4 and the minting note in section 3; read it). Goal: daemon/auth side. (1) 'token create' refuses '@' in a local principal name. (2) A principal named <name>@<machine> is a visitor: can send, read own inbox, query; matched by exact name so it never takes over the daemon's own external:orchestrator wake long poll, liveness watch or handovers (check where those match by name, e.g. crates/bridle-daemon server/auth, supervisor). (3) 'token create --project' can print the token (a flag like --print or default output; pick simplest, since today it prints none) so it can be pasted on another box. Files: crates/bridle-daemon (auth/server), crates/bridle token subcommand, bridle-api types only if needed. Tests: @ refused, visitor can send/read inbox, visitor cannot act as the daemon's orchestrator, token printed. Docs: cli.md, api docs, CHANGELOG. Acceptance: just check passes. Model: Sonnet. Out of scope: config/routing (slice A), listening on a port (slice C). May touch crates/bridle CLI files slice A also touches (different subcommand); merge one after the other if conflicts.
