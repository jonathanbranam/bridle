Slice A of 7gk7 (br-01ff). Read docs/tickets/open/tickets-through-the-bridle-binary-7gk7.md and docs/README.md 'How the folders work'; see the existing external scripts for the current behavior: ../workflow-instructions/scripts/new-ticket.sh and ticket-conventions.md (if reachable; else the README). Goal: a new 'bridle ticket' subcommand group (pure CLI, local files; no daemon start-up code). (1) 'bridle ticket new "<title>" [--repos a,b] [--needs ..] [--see ..]': mints a fresh 4-char ID from abcdefghjkmnpqrstuvwxyz23456789, unique across open/ and resolved/ in the repo; writes docs/tickets/open/<slug>-<id>.md with frontmatter id, title, opened (today, UTC date as today's tickets use), repos (default: the project name), changes, specs, needs, see, and an empty body section agents fill; prints the path. Also creates the matching bridle task (body 'original id: <id>\n<path>', as docs/README.md describes) when a daemon is reachable; --no-task to skip; a missing daemon is a warning, not an error. Creates the open/ and resolved/ folders if missing. (2) 'bridle ticket resolve <id>': sets a new 'closed:' frontmatter timestamp (ISO date-time UTC), git-mv-free move from docs/tickets/open/ to docs/tickets/resolved/ (plain file move; leave committing to the caller); refuses unknown/ambiguous ids; does not touch the task. Root is docs/tickets relative to the repo root (find via git), no config. Put ticket logic in its own module (frontmatter parse/write, id mint, find by id) so slice B reuses it. Tests in temp dirs: id uniqueness, file name and frontmatter, new with no daemon, resolve moves and stamps closed:, unknown id. Docs: cli.md, docs/README.md, CHANGELOG. Acceptance: just check passes. Model: Sonnet. Out of scope: check/set/link checking and role rules (slice B), templates, spikes folder, ticket-state-without-moving-files (p2ys), k7tm, xe5c.
