Design: docs/questions/open/email-and-texting-for-bridle-and-track-web-rs7p.md ('mail reaches the machine running the project', 'Delivery to the advisor'). Builds on Mail 1 and hw6c 1 (br-f3ec, the owner record on bridle/state). (a) A bridge takes a project's mail only while its own daemon owns the project (read the owner record); mail for other projects is left alone in the bucket. (b) Mail for a project no box serves waits; after a configurable time (default 1 hour) the allowlisted sender gets 'not delivered yet: no machine is running <project>' once. (c) An unknown project name gets a reply listing valid ones (allowlisted senders only). (d) Advisor liveness: the advisor launcher records a pid file (like orchestrator.pid; scripts/claude-advisor); the bridge treats the unnamed advisor as running only while that pid is alive; running -> external:advisor, else external:orchestrator. Add 'bridle wait-for-wake --mail', a mail-only waiter for the advisor. (e) The recipient's 'got it: <what was done>' one-line reply goes to the sender via the bridge. Tests with fakes. Docs (cli.md, advisor role file), CHANGELOG. Acceptance: just check passes. Model: Sonnet. Out of scope: live AWS, Telegram, mail for track-web's own subdomain.
