1. `bridle token pair [--machines <m>,...] [--projects <p>,...] [--roles <r>,...] [--tokens role,peer] [--rotate] [--dry-run]`, human only (human or human@<machine>). 2. Role tokens per the Design: mesh over selected machines, projects, roles; ssh via plain `ssh <host>` with `bridle` on the remote PATH; tokens only through ssh stdin/stdout and memory, never argv, logs, output or any file but the target credentials.toml (0600); written as `[<role>] <project>` same machine, `[<role>.<machine>]` other machines (k7mw; br-8b98 already reads `[human.<machine>]`). Idempotent (an entry that works, checked with GET /v1/status, is kept), `--rotate`, `--dry-run`, partial failure reports and non-zero exit, summary per machine with no token values.
3. The ONE token-role list in code (today: human (remote only, as human@<machine>), orchestrator, advisor, aide, mail; comment that product-manager shares the advisor token). Session launchers (crates/bridle-daemon session.rs and wherever BRIDLE_AS is set) and token pair both read it. A test fails if a launcher sets BRIDLE_AS to a role not in the list.
4. Agents' deny lists get `Bash(bridle token *)`: check crates/bridle-daemon/src/config.rs built-in disallowed_tools and workflow/base/roles/*.md; there is none today. Verify the human-only command check in the daemon/CLI too.
5. The spec design/specs/token-pairing.md (format docs/design/specs.md; check how `bridle workflow spec` / crates/bridle-spec read it) with the Design's requirements and one scenario each, including the verbatim requirement "All roles that need a token pairing are paired when the command runs." and the new-role scenario. Scenarios for peer/opt-out are added in part 2.
6. Docs: docs/design/cli.md, principals.md (grep), CHANGELOG.md; docs/context/add-a-machine.md (br-hua2): if it exists, point it at this command instead of the by-hand steps, else leave a note on the thread.
Tests: a fake ssh script on PATH (temp dir prepended to PATH only in the child command of the test; no real ssh); cover: defaults mesh, narrowing, idempotent second run changes nothing, partial failure, dry-run, no token in argv/output, new-role-in-list gets paired.
