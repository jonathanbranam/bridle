Goal (docs/design/impact-and-conflicts.md, 'The impact registry'): `bridle impact set <task> [--modify ID].. [--add-under ID].. [--remove ID].. [--files GLOB]..` and `bridle impact show <task>`. Impact is a field on the task record: persisted in the state branch record (crates/bridle-daemon/src/state_branch.rs), the SQLite tasks store (store.rs; schema migration) and rebuildable by `bridle rebuild`; wire types in crates/bridle-api/src/types.rs (all clients and the daemon together, per CLAUDE.md); API endpoint and CLI in crates/bridle (cli.rs, commands.rs). Only a task in open/planned/claimed may be set. Ids are validated by shape (r-/s-/g-/a- plus hex) only. Update docs/design/storage.md, cli.md, impact-and-conflicts.md (Built section).

Acceptance: just check passes; store test, rebuild round-trip test, CLI e2e for set/show. Model: Sonnet. Out of scope: checking overlaps (next task), actual-vs-declared diffing. Same files as other schema-changing tasks: don't run in parallel with another that edits store.rs schema.
