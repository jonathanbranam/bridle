URGENT: CI on `main` has failed on every push since c533cb0 (first failing run 17:49 UTC;
2b0b194 the last green). Fix and get CI green is the whole point of this task.

What happened: br-29f9's `[branches]` merge defaults the integration branch to `main`, so
`bridle spawn` now runs `git worktree add -b bridle/<name> <path> main`. Tests create their
throwaway repos with plain `git init` (e.g. `crates/bridle/tests/cli_e2e.rs:40`,
`crates/bridle-daemon/src/worktree.rs:310`, `tasks.rs:938`, `state_branch.rs:721`), which on
ubuntu-latest (CI) makes the initial branch `master`, not `main` -- `git worktree add`
then fails with `fatal: invalid reference: main`. About 21 tests fail across cli_e2e,
governor, lifecycle, renew, spawn_messaging and context_governor. It passes locally because
this machine's global git config sets `init.defaultBranch=main`, masking the bug.

Fix, three parts:
1. Every test that does a plain `git init` for a throwaway repo must create it with `main`
   as the initial branch explicitly (`git init -b main`, or `git init` + `git checkout -b
   main` if `-b` isn't available in the CI git version -- check), everywhere `git init`
   appears in the test suite (grep for it across all crates, not just the four files named
   in the ticket).
2. Make tests run git isolated from the user's/CI machine's global git config (e.g. set
   `GIT_CONFIG_GLOBAL` to an empty file for the test's git invocations), while still setting
   `user.name`/`user.email` explicitly so commits work. This makes local runs match CI so
   this class of bug can't hide again behind a locally-customized `init.defaultBranch`.
3. In the daemon: when `[branches] integration` is unset (defaults to `main`) and `main`
   doesn't exist in a project's repo, fail fast at startup/config-load with a clear error
   naming the `branches.integration` setting, instead of every spawn silently failing later
   with `invalid reference`. Per rxe8's KISS/explicit-branch-rules stance: don't guess the
   branch from HEAD, just fail loud and tell the human to set it. A project on `master`
   sets `branches.integration = "master"` explicitly.

Acceptance: `just check` passes (fmt, clippy, full nextest); CI is green on `main` after
this merges (verify via the actual GitHub Actions run, not just local `just check`, since
the bug is CI-environment-specific); a regression test that a project whose repo has no
`main` branch and no explicit `branches.integration` setting fails at daemon startup/config
load with a message naming the setting (rather than failing later at spawn).

Out of scope: anything about branch rules' design beyond this fix (rxe8/br-29f9 already
shipped); CI infrastructure changes beyond what's needed to make tests git-config-isolated.

Model: Sonnet (spans multiple test files across crates, a startup-time validation change,
and needs actual CI verification, not just local judgment calls about git behavior).
