The human (2026-09-28): "We should have an estimated size on these tickets to indicate small
tickets that can be picked up when we're running short on budget."

Brief: add an estimated size to tasks (S/M/L, optional, default unset) so the PM and manager
can pick small ones when the budget is low. KISS: one optional field on the task record
(crates/bridle-daemon task store + state branch record format; see docs/design/storage.md
and the tasks docs), set via `bridle task new/edit --size S|M|L`, shown in `bridle task
show`, `bridle task list` and `bridle queue`. Optionally let `bridle queue` (or task list)
filter by size. No automatic selection logic: the manager reads the size and decides.
The queue's ordering stays PM-owned tiers.

Acceptance: `just check` passes; tests for set/show/list and round-trip through the state
branch (and a rebuild from it, if P0-5 rebuild exists); docs/design/cli.md and storage.md
updated; the manager skill/role mention of size when budget is low is one line at most.

Out of scope: derived/measured sizes, auto-splitting, budget-aware auto-picking.

Model: Sonnet (wire types + store + CLI).
