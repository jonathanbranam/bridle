Part of onboarding data-contracts (docs/context/onboarding-data-contracts.md §3, §7 step 2;
go-ahead from the orchestrator/human 2026-09-28). workflow/base/skills/worker/SKILL.md:28
hardcodes `just check` as the definition of done. data-contracts uses `make check`; bridle
itself keeps `just check`. Every future pack/project will want its own command.

Brief: make the check command a per-project binding instead of a hardcoded string in the
base skill.
- Add a place for it in project config, e.g. a `[commands]` table in .bridle/config.toml
  with a `check` key (default "just check" if unset, so bridle's own project needs no
  change) -- check crates/bridle-daemon/src/config.rs for the Config struct shape before
  adding a field, and follow its existing conventions (workflow, packs are the closest
  precedents).
- Change workflow/base/skills/worker/SKILL.md so it references the project's check
  command instead of the literal `just check`. Two ways to do this, pick whichever fits
  bridle sync's existing rendering model (crates/bridle-daemon/src/sync.rs) best: (a) a
  template placeholder that sync substitutes when rendering .claude/skills/bridle-worker/
  from resolved layers, or (b) prose that tells the worker to look up the command itself
  (e.g. `bridle config get commands.check`, if such a read path exists or is trivial to
  add) rather than a hardcoded string. Prefer (a) if sync already does similar
  substitution elsewhere; don't build new machinery beyond what's needed for this one
  binding.
- Update bridle's own .bridle/config.toml to set `commands.check = "just check"`
  explicitly (or confirm the default covers it) so nothing changes for bridle itself.
- Update docs/design/workflow-layers.md and docs/design/cli.md if the binding mechanism
  needs documenting there.

Acceptance: just check passes; a test (or documented manual check) that sync renders
`just check` for bridle's own project and would render a different command for a project
whose config sets one; bridle's own worker skill still says `just check` after `bridle sync`.

Out of scope: building workflow/packs/python/ (separate task, depends on this one landing
first since the python pack's own check-related rules assume this binding exists).

Model: Sonnet (touches config schema and the sync renderer).
