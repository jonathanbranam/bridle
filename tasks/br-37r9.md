Goal: the removal step that runs after a task lands (the 'cleanup: removed agent X, branch Y' note; grep cleanup in crates/bridle-daemon/src/server.rs, supervisor.rs, lib.rs and the land command in crates/bridle/src/commands) must NOT remove the worker or its worktree when the worker still holds other work: (a) uncommitted changes in its worktree, (b) another local branch with commits not on the integration branch, (c) another claimed task assigned to it, (d) a running background job. In that case keep the worker, record a note on the landed task naming which condition held, and message the manager once; the landing itself still succeeds. Normal case (nothing else held) stays as today. Acceptance: just check passes; tests for each of the four conditions keeping the worker, and the clean case still removing it. Docs: docs/design/agent-host operating-model.md or the doc that describes cleanup (grep), cli.md if flags/output change, CHANGELOG. Migration: none (daemon behaviour). Model: Sonnet. Out of scope: reassigning workers to a second task (policy), killing background jobs.
