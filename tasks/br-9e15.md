Goal: (1) New task IDs use the ticket alphabet (abcdefghjkmnpqrstuvwxyz23456789, 4 chars) instead of hex; existing task IDs unchanged. (2) The first task made from a ticket takes the ticket's ID (prefix + ticket id, e.g. br-k7tm); later tasks from the same ticket get fresh IDs. The explicit map stays both ways (ticket frontmatter tasks:, task body 'original id:'). (3) One ID space: 'bridle ticket new' checks a new ticket ID against existing task IDs too (it already reaches the daemon), and the daemon refuses a new task whose ID matches a ticket's unless it is that ticket's first task. Note: 'bridle ticket new' no longer creates a task by default (k7tm decision 1); whichever command creates a ticket's task must pass the ticket ID. Docs: storage.md (task ids), cli.md, docs/README.md and the tickets rule, CHANGELOG. Tests: alphabet; first task gets the ticket ID; second gets a fresh one; collision refused. Acceptance: just check passes. Out of scope: the speakable-IDs question (nkd9) and whether tickets and tasks merge (the rest of k7tm).
