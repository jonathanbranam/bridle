The human (2026-09-28), on meta-notes' first daemon start: "the manager didn't startup
automatically, that should happen by default; the roles we need should just start".

Today `autostart` defaults to false for every role, the built-in manager included
(docs/design/agent-host/roles-and-config.md; startup behaviour in daemon.md; code in
crates/bridle-daemon/src/config.rs where the built-in roles are defined). meta-notes had to
add `autostart = true` to its `[roles.manager]`.

Change: the built-in `manager` role defaults to `autostart = true`, so a project with no
role config gets a manager agent (named `manager`) at daemon start. Workers stay false
(spawned per task), and so do the product-manager and any other role (KISS: only the manager
is needed to run a project; a project can still set autostart on any role, including
`autostart = false` on the manager to turn it off). Make sure explicit project config
overrides the default both ways.

Check the startup path: an autostarted manager must not double-spawn when `resume_on_restart`
also brings back a previously-running manager, and a daemon started with no claude/quota
(tests) must not break. Many existing tests spawn a daemon with default config and then
count agents; expect to update those to set the manager's autostart false (or use a fixture
config) rather than weakening the default. Never spawn real claude in tests (fake-claude
only).

Acceptance: `just check` passes; tests that (a) a default config starts a manager at daemon
start, (b) `autostart = false` on the manager in config suppresses it, (c) no duplicate
manager when it was resumed after a restart; docs updated where the default is stated
(roles-and-config.md, daemon.md, and .bridle/config.toml comments if any mention it).

Out of scope: autostart for other roles, ordering of role startup, meta-notes' own config
(the orchestrator trims it on the trial branch).

Size: small. Model: Sonnet (test churn across the daemon suite).
