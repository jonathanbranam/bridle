Critical: main is red on ubuntu since br-rztb landed (5aa62200), every run: e.g. https://github.com/jonathanbranam/bridle/actions/runs/37987916350
  gateway_test a_replaced_binary_is_re_executed panicked at crates/bridle/tests/gateway_test.rs:236: the fake ran in place of the gateway: exit status: 1

Diagnosis (orchestrator): crates/bridle/src/gateway.rs:335 treats any process with INVOCATION_ID set (Linux) as a child of bridle's systemd unit. systemd sets INVOCATION_ID for every service and children inherit it: the GitHub runner is a systemd service, so the test's gateway thinks it is unit-managed and exits non-zero on a replaced binary instead of re-executing. A real bug, not only a test one: a gateway started from anything under any systemd service would be misdetected.

Fix: detect our own unit, not any unit. E.g. compare INVOCATION_ID with `systemctl --user show -p InvocationID --value bridle-gateway.service`, or have the unit set an explicit marker (Environment=) and check that (then the unit needs reinstalling: say so and update the migration note). Check the macOS XPC_SERVICE_NAME check is already specific to our label (it is: == LABEL). Add a unit test for 'INVOCATION_ID set but not ours => not managed'.
Acceptance: just check passes; the gateway test passes with INVOCATION_ID set in the env (run it with INVOCATION_ID=x exported to reproduce the CI failure locally first). Model: Sonnet. Size S.
