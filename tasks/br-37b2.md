Bug: worker `python-pack` (a-s3ije) had just handed off for a context renewal when the
daemon restarted. After the restart it showed idle with context 0; each `bridle resume`
came up idle, then died on its first turn with no tokens used: turn.ended
{is_error: true, subtype: "error_during_execution", cost_total 0}, then agent.exited
{code 1, reason "eof"} (event numbers 23841-23882 in that project's events). Budget
governor was holding at the time. Restarts happen at every deploy across all projects, so
resumed agents that die on turn one are a serious reliability hole.

Likely cause, unverified: the agent's stored Claude Code session id points at the session it
was renewing away from, or at one that never started, so `claude --resume <id>` fails at
once. This is a diagnose-then-fix task:
1. Reproduce with fake-claude (crates/bridle-claude/tests/fake-claude.py): an agent that
   starts a renewal (handoff) and is then resumed after a daemon restart. Read the renew
   and resume code (crates/bridle-daemon supervisor/renew, and where the session id is
   stored and updated) to see which session id is persisted at each step and when.
2. Fix so a resumed agent always resumes a session that exists: e.g. persist the new
   session id only once the new session has started, or, if the stored session can't be
   resumed, fall back to a fresh session seeded with the handoff instead of dying
   (whichever the code makes simpler and safer; say which in the final message).
3. If resume fails at the process level, the daemon should log claude's stderr/exit reason
   at warn so the cause is visible next time (small addition; don't build more logging).
If you cannot reproduce it from the code after a reasonable look, say so, add the
stderr-logging from (3) plus a test of the stored-session-id invariant you did verify, and
report what evidence would settle it.

Acceptance: `just check` passes; a regression test for the reproduced sequence (or, if not
reproducible, the invariant test plus logging); docs/design/agent-host/ updated if the
renew/resume sequence changes.

Out of scope: r3nh (hold check order in renew), budget policy, restart-time ordering.

Size: medium (diagnosis). Model: Sonnet.
