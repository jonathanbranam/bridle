Read docs/design/storage.md (task records, the state branch, rebuild from it), the task code in crates/bridle-daemon (store, task create), crates/bridle-api/src/types.rs (Task), 'bridle task show' in crates/bridle.
Goal: a created_by field on Task, set at creation to the creating principal, shown by 'bridle task show' and in the API/JSON, and kept in the task record on the state branch so a rebuild from it restores it. Existing tasks are backfilled from their task.created event's actor (and, for tasks only on the state branch, the first thread entry or a safe default 'unknown'; say what you chose). The migration is automatic and idempotent and must NEVER prevent daemon start-up: a failed backfill for one task logs and leaves it unknown; a new column is nullable. Old clients/old task files without the field still parse (serde default). Tests: new task has created_by; backfill from events fills old tasks; a task with no created event stays unknown without error; rebuild from the state branch keeps created_by; show/JSON print it; start-up with an un-migrated database succeeds. Docs: storage.md, api.md, cli.md, CHANGELOG. Acceptance: just check passes. Model: Sonnet. Migration: automatic backfill described above. Out of scope: watchers, wake changes. Do not touch the 1M-event scan in principal_wake.rs (task 3 removes it).
