Read docs/design/human-web-ui.md (all, esp. sections 1, 3, 5) and ticket essy first. Goal: the 'bridle gateway' subcommand and a new crates/bridle-gateway library (axum). The optional gateway config section in ~/.bridle/config.toml (bind address; default loopback; refuse 0.0.0.0 unless explicitly set), serve, and GET /api/v1/health. ALL routes live under /api/v1 from the start (task 7 later only adds ts-rs types and the stale-types test). Follow how bridle-daemon builds config and the axum server; keep the gateway independent of the daemon crate if possible (use bridle-api). It never touches the daemon or its start-up path. A bad or missing gateway config must give a clear error from 'bridle gateway' only; no other command may be affected. Tests: server starts and answers health; bad bind rejected; config absent or malformed does not affect other subcommands. Docs: a short docs/design/agent-host or cli.md entry, CHANGELOG. Acceptance: just check passes. Model: Sonnet. Migration: none (new optional machine config). Out of scope: discovery, login, UI serving, service install.
