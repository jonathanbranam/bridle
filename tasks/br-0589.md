Goal: 'the agent for this branch' is always exactly one agent. Ticket: docs/questions/open/clean-up-agents-when-their-work-lands-k3wp.md, 'One agent per branch'. Today a manager can spawn a second agent into another agent's existing worktree and branch (python-pack-2 onto bridle/python-pack), leaving two agents on one branch. Do: in the spawn path that takes an existing worktree or branch (added with the context governor; find it in the crates/bridle-daemon spawn code and the CLI flag), refuse with a clear error when another non-removed agent, running or stopped, already holds that worktree or branch, and name the fix in the error: renew that agent (bridle renew) or remove it first. Renew must keep working (it reuses the branch for the same agent). Update docs/design/agent-host and the manager role and skill wording if they tell managers to spawn onto an existing branch. Acceptance: just check passes; tests for the refusal, for spawn after the old agent is removed, and for renew. Model: Sonnet. Out of scope: cleanup on landing (br-7d81). Independent of it.
