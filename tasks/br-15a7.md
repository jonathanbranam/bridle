URGENT, small, docs only. Cause found in fx7x: workers running pkill -f "just check" killed the live orchestrator twice on 2026-09-29, because pkill -f matches any process whose argv contains the pattern (the orchestrator's launcher argv contained it). The launchers are fixed (5278556); this is the standing rule. Do: 1) add workflow/base/rules/no-kill-by-name.md, frontmatter and style like workflow/base/rules/yagni.md and kiss.md (look at how locked/severity is set; make it severity must, and locked if the neighbouring safety rules such as existing-projects.md are locked), roles: all roles. Content: never use pkill -f, pgrep -f piped to kill/xargs kill, killall, or kill by a pattern match of any kind; kill only a pid you started and own: $! of a background command, the shell job id (kill %1), or pkill -P $$ for your own children; if a stray process seems stuck and you didn't start it, leave it and report it on the task thread. Include the one-line why (the orchestrator was killed twice). 2) Add a one-line pointer in workflow/base/roles/worker.md and the worker skill (workflow/base/skills/worker/SKILL.md) only where they mention stopping jobs or check runs; if they don't, add one short line under the worker's Never list. 3) If any rule-list snapshot test or bridle rules/prime test enumerates rules, update it. Acceptance: just check passes; the rule appears in bridle rules for the worker role (say how you verified). Model: Haiku. Out of scope: hooks or permission denies for pkill (a later idea), launcher changes.
