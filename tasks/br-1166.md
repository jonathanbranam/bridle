Design: docs/questions/open/email-and-texting-for-bridle-and-track-web-rs7p.md (sections 3, 'The human's answers', 'Delivery to the advisor'). Build the INBOUND half of 'bridle mail run' (a separate subcommand or crate beside serve; holds an external:mail token; only calls the send and inbox endpoints; keeps the AWS SDK and MIME parsing out of the daemon). Poll the S3 inbound prefix via a small trait (real AWS impl + an in-memory fake: tests never touch AWS). Accept only if DMARC pass for the From domain, From on the allowlist ([mail] allow = addresses and @domains; a domain entry still needs DMARC pass), spam/virus verdicts pass, and not an auto-reply/bounce; otherwise drop silently and log. Parse: <project>@dev.branam.us and <project>+t-<task>@ (note on that task's thread); subject plus new text with quoted history and signature stripped; HTML converted to text not trusted; body size cap; .md/.txt/text/* attachments kept (1 MB cap each) under the project's inbox with the path in the note, others dropped and the drop noted; tag every message 'via email' with the SES message id. Delivery: to external:advisor when the advisor is 'running', else external:orchestrator (advisor liveness = the next task; for now a config switch or always orchestrator). Delete/ack processed objects. Config in docs, CHANGELOG. Acceptance: just check passes; fake-S3 tests for each accept/reject rule, address parsing, quote stripping, attachments, routing. Model: Sonnet. Out of scope: outbound mail, digest, reply tokens, project ownership gating, live AWS, the human's AWS setup (br-fc05, theirs); do not block on it.
