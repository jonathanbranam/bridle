The daemon waits for a quiet point (every agent idle) with a timeout that gives up and reports rather than cutting work off; then flushes and pushes the state branch (we2r path), stops agents through the shutdown path, and exec's current_exe() (std::os::unix::process::CommandExt::exec: safe Rust, no unsafe) with the same args, so PID and terminal stay and Ctrl-C works. The new process rebinds the same port; clients retry through the gap. Record which agents were running before the exec (e.g. in the store) so the new process can act on it. (b) After startup, resume EVERY agent that was running, workers too, not only resume_on_restart roles; each gets a message that the daemon restarted for an upgrade and to carry on. (c) A wake to the orchestrator before and after (commit, what resumed); nothing to the human's inbox unless it failed. Wire types in bridle-api/src/types.rs, clients and daemon together; docs in step (daemon.md, api.md, cli.md), CHANGELOG.
