The decided model:
- The DAEMON enforces reviews, not the manager or any agent. The worker moves its task to "ready for review"; bridle reads the task's metadata and the workflow rules, spawns the required reviewers, and messages the manager only when every required review is signed.
- Required reviews come from a project policy (e.g. security review on every task) and/or a per-task flag ("requires security review", "requires human review"). A required review is NEVER silently skipped (no size/docs-only/wind-down skips unless the human adds them).
- Reviewers and the worker talk ONLY on the task (comments and status changes), never by direct message: the permanent record, kept to tune reviewer and worker guidelines and cost. The record must show what each review cost (tokens/USD per reviewer on the task).
- A reviewer must approve and SIGN before the task moves on. Signing uses the reviewer's bridle token (working assumption: tokens are secure; hardening is 2bzw's, not here). A human review required by policy is signed the same way with the human's token.
- Reviews are opt-out per project through the base rules mechanism (workflow-layers.md).

Slices (each a task, created open, in order):
A. Task state and metadata: `in_review` state, `bridle task ready-for-review`, per-task review requirements + the policy lookup (which reviews are required for this task); state machine, storage (+ state branch mirror), API, CLI, docs. No reviewers yet.
B. Signed review records on the task: a review verdict (approve / changes-needed) is a signed thread entry; signature scheme settled in this slice (note: the store keeps token HASHES only, so say how the daemon verifies; propose one and flag it); `bridle task review` command for reviewers and the human; `bridle task show` shows required vs signed.
C. The daemon spawns required reviewers when a task enters in_review: reviewer roles (code, security), comment-only communication with the worker (no direct send to the worker), cost recorded per review on the task, worker resumed or told via the task thread on changes-needed, one re-review cycle.
D. The gate: land/done refuses until every required review is signed; the manager is messaged only then; docs, rule files for policy and opt-out; role text for worker/manager.
Each slice: just check passes; Sonnet. Branch-only/parked until the human has reviewed the design if it touches the spawn path (C).
