Recommended shape (for the human to confirm; flag differences, do not silently pick):
- Who reviews: a workers cannot spawn agents (spawn is refused for role worker), so the MANAGER spawns the reviewers. Sequence: worker finishes, passes just check, hands off -> manager spawns an independent reviewer (never the implementer; fresh context; read-only: no edits, no commits) -> reviewer reports findings as task comments with a verdict pass/changes-needed -> on changes-needed the worker (resumed) or a new worker fixes, then re-review -> only on pass the manager lands. This is equivalent in effect to "must pass before work is done"; the worker's done report says "awaiting review".
- Two reviews, independent: code review (does the diff match the brief and the design docs, tests meaningful, KISS/YAGNI, docs updated) and security review (secrets, auth/token handling, injection, path traversal, unsafe input, new network surface, permissions). Each is its own reviewer agent with its own short role prompt, base model Sonnet or stronger; the security one runs only when the diff touches code (skip for docs-only diffs: the diff itself decides).
- Opt-in/out: a base rule workflow/base/rules/review.md, ON by default in bridle's own project; a consumer disables it with `override: disable` plus a reason, or keeps only one of the two (separate rule names: review-code, review-security). Cost knob: a size/diff-lines threshold below which review is skipped (default: skip under ~30 changed lines and docs-only).
- Bridle code: a reviewer role (workflow/base/roles/reviewer.md), a `bridle review` helper or manager-skill step is optional; start with roles, rules and the manager skill text, no daemon change. Only add daemon support (an in_review task state) if the text-only version proves too loose, as a follow-up.
- Budget: each review costs tokens; the rule says to run them on the same account budget and to skip when the budget governor is in wind-down.

Tests: whatever the rule/render pipeline tests (bridle rules / sync rendering) need so the new base rules and role render and can be disabled by override. Docs: workflow-layers.md, roles-and-lifecycle.md (turn the Reviewer paragraph from future to built, as far as built), CHANGELOG. Acceptance: just check passes. Model: Sonnet.
Out of scope: an in_review daemon state, automatic fix-up loops beyond one round trip, reviewing the human's existing projects until they opt in.
