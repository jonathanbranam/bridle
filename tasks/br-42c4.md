Context: many files in docs/tickets/open/ describe work already done: e.g. z4hd (task br-f919 integrated) and by23 (br-f05d integrated) are still open, which makes the backlog look bigger than it is and misleads triage. Conventions for moving tickets: docs/README.md; existing examples in docs/tickets/resolved/ (a 'Resolved' note with the commit or task id). Tool: 'bridle ticket' commands if one moves tickets (check 'bridle ticket --help'), else git mv.
Goal: for every ticket in docs/tickets/open/ and docs/spikes/open/ that has a task (frontmatter tasks:, or a task whose first body line is 'original id: <id>'; use 'bridle task search <id> --json') and ALL such tasks are integrated or dropped, verify the ticket's own Fix/Shape section is actually covered by the task summary (read the task summary and a quick look at the code or CHANGELOG), then move it to resolved/ with a short Resolved note naming the task and commit. If a ticket is only partly done, or you are not sure, leave it open and add one line under it saying what is left. Do not touch tickets with open or planned tasks, or with no task. Do not edit ticket content beyond that. Fix broken [[links]] if the move breaks them, and run 'bridle ticket check'.
Acceptance: just check passes and 'bridle ticket check' is clean (warnings about missing kind are expected until v3dk slice B). Model: Haiku. Migration plan: none (docs only). Lands normally. Out of scope: opening new tickets, re-triaging priorities, ticket kinds.
