original id: zm95

Bug: the daemon's graceful shutdown never finishes while any client holds the SSE event
stream open (`bridle tui`, `bridle events --follow`). In crates/bridle-daemon/src/lib.rs the
shutdown task stops agents, flushes tasks, removes the registry entry and daemon.json, then
signals axum's `with_graceful_shutdown` and awaits `serve_task`, which waits for every open
connection. The SSE handler in crates/bridle-daemon/src/server.rs ends only when its
broadcast receiver reports Closed, which needs all senders dropped; the daemon's own
emitter still holds one. So the process lingers, and since daemon.json is already gone it
looks stopped. Bites every restart. The human: quitting the TUI made it stop at once.

Fix (both, small): (1) make the events stream end when shutdown begins (select on the
shutdown signal / a cancellation token in the stream, so clients see the stream close);
(2) bound the `serve_task.await` with a timeout (e.g. 5s) after which the daemon exits
anyway, logging a warning.

Acceptance: `just check` passes; a test that starts the daemon (or the axum server with the
shutdown future), opens an events stream, triggers shutdown, and asserts the server task
finishes promptly (well under the timeout) with the stream client still connected and
seeing the stream end. Update docs/design/agent-host/ only if it describes shutdown order.

Out of scope: anything else in shutdown, the TUI.

Size: small. Model: Sonnet (async shutdown ordering is easy to get subtly wrong).
