Look at: how the TUI (crates/bridle-tui) reads the API, docs/design/agent-host/daemon.md and principals.md (auth, tokens), ~/.bridle/config.toml [machines]/[projects] discovery (k7mw), how --for-human to-dos and questions are listed in the API.

Goal: ONE design doc, docs/design/human-web-ui.md, for the human to review. NOTHING is built: no code, no server, no prototype. Stop when the doc is written, committed on the branch, and reported; the human decides what next.
The doc covers, each with a recommendation and the main alternative in a line or two:
1. What the human sees: the to-do list and the decisions (questions to the human), organized by project, laid out to run through and check off quickly (a rough text sketch of the screens; what one item shows; what checking off or answering does in API terms; priority order; phone-friendly or not).
2. Across projects and machines: one UI for every project, including other machines' daemons. How it finds daemons, how it fans out, what it needs from 3ehu.
3. Where the server runs: a 'bridle ui' process vs served by one daemon vs per daemon; port; start/stop; survives restarts.
4. Browser auth: how the human's browser authenticates (loopback only first? token in a URL/cookie? HTTPS and remote access later, u6wk), where the token comes from, what a browser can never do.
5. Stack: the simplest thing (e.g. server-rendered pages plus small JS, no build step, Rust in the workspace) and why; no SPA framework unless justified.
6. A cut into build tasks (small, in order), and what to prototype first with the prototyper role (br-a4ea, landed: workflow/base/roles/prototyper.md) if the human wants prototypes before choosing.
7. Migration: whether projects' files or config change (aim: none).
Keep it short (3-5 pages). KISS, YAGNI: first version is local, read plus check-off/answer, nothing else. Acceptance: the doc exists, linked from docs/README.md and from the essy ticket; just check passes (docs only). Model: Sonnet. Out of scope: any code, the TUI, a mobile app, notifications.
