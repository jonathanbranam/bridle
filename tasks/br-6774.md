Goal (docs/design/impact-and-conflicts.md, 'The conflict protocol' steps 1-2): when impact check finds a conflict-level overlap between two tasks, the daemon opens a conflict record (id C<n>) with a thread between the two claimants (or the manager for an unclaimed task) and injects one message into both agents' sessions naming the other task and the overlap. `bridle conflict list` and `bridle conflict resolve C12 --compatible '<reason>' | --order A,B | --merge-into A`: compatible records the reason; order adds a blocks edge (A blocks B) using the existing dep code; merge-into records it. Reuse the tasks thread/question machinery (docs/design/coordination.md) if a conflict can be modelled as a thread on a task; otherwise a small conflicts table + state-branch record. Idempotent: the same overlap doesn't open a second conflict. Escalation to manager/human is out of scope. Docs: impact-and-conflicts.md, storage.md, cli.md.

Acceptance: just check passes; tests: conflict opened once, both agents messaged, each resolve mode. Model: Sonnet. Runs after the impact check task.
