Goal: migrations run automatically.
1. 'bridle serve' applies the project's pending migrations at start-up, using the same code and recording as 'bridle migrate' (.bridle/migrations.toml, .bridle/migrations.log, project.migrated events; post the events once the daemon is up). A starting daemon catches up whatever it missed while down, and an upgraded binary migrates every project as each daemon starts.
2. A migration failure must NEVER stop the daemon starting: log it, file an incident (or the nearest existing loud, findable record), stop the run at that migration as 'bridle migrate' does, and carry on. A refusal for uncommitted changes in the files it edits is not a failure: skip, log, retry at next start.
3. Opt-out: '[migrations] auto = true' in .bridle/config.toml, default on. auto = false skips the start-up run; 'bridle migrate' still works by hand.
4. Opt-in migrations: a flag on a migration in the MIGRATIONS list (e.g. manual_only, default false). Start-up and 'bridle migrate --all' skip them; plain 'bridle migrate' lists them as pending-manual and runs one only by id ('--only NNNN-name' or simplest equivalent). None is opt-in today; use a test fixture.
5. Update docs/design/migrations.md (its 'Never automatic' rule now says the opposite), the config reference, docs/design/cli.md if the CLI changes, CHANGELOG; add a short 'Built' note to the ticket, don't close it.
Tests: pending migration applied at serve start-up and recorded; auto=false leaves it pending; opt-in skipped at start-up; failing migration leaves the daemon up and files the record; nothing pending touches no file and makes no commit noise; uncommitted-changes refusal doesn't fail start-up.
Acceptance: just check passes. Model: Sonnet.
