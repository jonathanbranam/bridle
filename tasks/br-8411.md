Ticket: docs/tickets/open/bridle-without-a-clone-of-its-repo-mrhe.md ('The human on the sketch' and 'Settled'). Decisions: projects that point at a local bridle clone (workflow = a path) keep updating automatically at bridle sync, as today; projects on an installed binary get a vendored copy that changes only when the human runs an update (opt-in, like OpenSpec). Build: (1) 'bridle init' (or the existing init/onboarding path; check docs/design/cli.md for what exists) for a project with no workflow path copies the base workflow into the project (e.g. .bridle/workflow/, committed by the human, not by bridle) from a source: the local clone if there is one, else fetched from GitHub at the tag matching the binary's own version (git clone --depth 1 --branch v<version> into a temp dir; the URL comes from config with a default; a network failure is a clear error). (2) 'bridle workflow update [--to <tag>]' refreshes the vendored copy and prints what changed; nothing else ever changes it. (3) Path resolution (NUC A's shared resolver) prefers the project's vendored copy when 'workflow' is unset. Tests with local git repos as the source (no network). Docs (workflow-layers.md: reconcile with the 'updates apply automatically' decision by stating both modes; cli.md), CHANGELOG. Acceptance: just check passes. Model: Sonnet. Out of scope: embedding the workflow in the binary, release binaries, the session command (mrhe 1), touching any existing project (the human decides when to run it).
