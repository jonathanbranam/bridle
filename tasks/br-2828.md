Ticket: docs/questions/open/one-machine-owns-a-project-hw6c.md (Shape 2). A clone can be marked tools-only in ~/.bridle/config.toml (machine scope), e.g. [machine] tools_only = ["/home/<user>/src/bridle"]. In such a clone: (a) 'bridle serve' refuses with a clear message; (b) bridle installs pre-commit and pre-push git hooks that refuse, saying why (--no-verify remains the deliberate override); do this from a command that is safe to re-run (e.g. 'bridle machine mark-tools-only <path>' or as part of the existing sync/doctor path; pick the simplest) and never clobber a user's existing hooks (chain or refuse to overwrite); (c) scripts/claude-orchestrator and scripts/claude-advisor refuse to start there, telling the user to run in the served project's workspace. Reuse the machine-config reader from NUC task A (br-4fd6). Tests: serve refusal, hook install idempotent and blocks a commit in a temp repo, scripts refuse (stub claude). Docs (cli.md, nuc-host.md), CHANGELOG. Acceptance: just check passes. Model: Sonnet. Out of scope: GitHub branch protection, mrhe. Run after br-f02f (scripts) and br-4fd6 (machine config).
