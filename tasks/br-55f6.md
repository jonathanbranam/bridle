Read docs/design/human-web-ui.md sections 1, 2 and 5 first. Goal: POST routes under /api/v1 to check off a to-do (daemon POST /v1/tasks/{id}/done), decline one with a reason (/drop), answer a task question (/answer), sent to the right project's daemon with the human's token (how the CLI finds it: principals.md). Only these actions exist; every other daemon operation is refused by the gateway. A missing token is a clear error. Tests: each action reaches the right fake daemon with the human's token; unknown action refused; missing token error. Acceptance: just check passes. Model: Sonnet. Migration: none. Out of scope: remote machines (task 9), login (task 6). Depends on gateway 3.
