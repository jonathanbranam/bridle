Goal: (1) A period belongs to the day it starts: start < end is the same day; end < start runs from start on a listed day to end on the NEXT day, whatever that day is, so the after-midnight part is matched against the PREVIOUS day's days. Same rule for [[budget.schedule]] (it shares in_window); do not split them. Existing 00:00-bounded split periods mean the same under both rules. (2) The reported end is when quiet actually ends: when periods touch or overlap, follow them to the last end (21:30-00:00 then 00:00-06:00 reports 'until 6:00 AM'); apply to the gate message, 'locked until', and the advisor refusal text. Guard against a loop (periods that cover the whole week: stop, cap the follow at 7 days and report the cap). (3) Docs: replace the two-block example with one overnight block and state the rule. (4) CHANGELOG: note that a period with end < start now also matches the morning after its start day, e.g. a 'sun' 23:00-07:00 period covers Monday morning even if 'mon' is not listed, and that it also applies to [[budget.schedule]]; the human updates their own ~/.bridle/config.toml (never edit it).
Tests, in_window directly with a fixed clock, for BOTH focus and budget.schedule callers: overnight period matches 23:00 on a listed day and 03:00 the next day whether or not that next day is listed; does not match 03:00 after an unlisted start day; start < end unchanged; end == start behaviour unchanged (check what it does today and keep it); the DST/ET handling in the existing tests keeps passing; touching split periods report the final end; overlapping periods report the last end; all-week coverage terminates.
Acceptance: just check passes. Model: Sonnet. Migration plan: no file migration: the rule is a superset for sensible configs and the human's file is theirs; the CHANGELOG note is the release note. Lands normally (the focus gate and budget schedule, not daemon start-up). Out of scope: per-project focus hours (mfgb).
