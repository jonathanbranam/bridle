Implement the proposal in docs/tickets/open/bridle-restarts-itself-q7rx.md, section 'Seen 2026-09-30'. Once a green build is waiting for a quiet point, the daemon refuses new worker spawns with a clear reason (model it on how a budget hold refuses spawns; grep the spawn path and hold check in crates/bridle-daemon, and upgrade.rs for the waiting state) until the restart has happened, so running workers drain to a quiet point; the existing 600s timeout then covers only a worker that never finishes. If the timeout gives up, lift the refusal (never leave spawns blocked forever). The refusal is visible in bridle status and the error names the reason. Tests: spawn refused while waiting, allowed after restart and after timeout give-up, existing upgrade tests still pass. Docs (design/agent-host restart doc, cli.md if the error shows there), CHANGELOG, update the q7rx section as done. Acceptance: just check passes. Model: Sonnet. Size S. Touches upgrade.rs like br-eb1f: start after br-eb1f lands. Must land by Thu 2026-10-01 10:00 ET. Out of scope: the rollback and quiet-point logic itself, daemon start-up code.
