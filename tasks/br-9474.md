Goal: talk about a task on its thread (rule workflow/base/rules/talk-on-the-task.md, read it) with one command, so agents can't do one half without the other. Ticket: docs/questions/open/task-talk-on-the-thread-n8tj.md. Do: (1) bridle send <agent> --task <id> [text or --file] writes the full text as a note on the task's thread and sends the recipient a short message that names the task and points at it ('<id>: note added', with the first line), (2) equivalent bridle task note <id> --notify <agent> (share one implementation; if that is more than a flag, ship only --task, the ticket allows either), (3) a message sent with --task is linked to it and shows in bridle task show <id>'s thread, (4) update the role prompts and skills for manager, worker and product manager under workflow/base/ to use it for briefs, done reports and review findings, and docs/design/cli.md and the messages and API docs. Wire change in crates/bridle-api/src/types.rs, so daemon and clients change together. Acceptance: just check passes; tests: note appears on the thread, recipient gets a short message naming the task, unknown task id is an error and sends nothing. Model: Sonnet. Out of scope: rewriting past messages into notes; enforcement of the rule. Touches the task store and cli.rs; run after br-1ac1 and br-f86f.
