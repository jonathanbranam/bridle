original id: r3nh

Bug: `bridle renew <agent>` while the budget governor is holding stops the old session
first, then refuses with "conflict: budget governor is holding ...", leaving the agent
`stopped` instead of idle in its old session (seen 2026-09-28 on pm-1; events show
stop_requested -> stopping -> stopped before the CLI error). Renewals happen constantly with
several projects' agents (context governor), so this matters.

Fix: find the renew path in crates/bridle-daemon (the renew handler in server.rs and the
supervisor/renew code; grep "budget governor is holding") and make the hold check happen
BEFORE any state change, so a refused renew changes nothing. Then check the AUTOMATIC
context renewal (htp6, the wind-down handoff path) takes the same code path and is
covered, whichever way the hold check ends up. Also decide: a renew replaces a session
rather than adding load, so it arguably needn't wait for a hold at all. Do NOT change that
policy unless the code makes it a one-line, obviously safe change; keep the existing
refusal and just reorder, and note the policy question in your final message.

Acceptance: `just check` passes; a test (fake-claude) that with the governor holding,
`renew` returns the conflict and the agent's state and session are unchanged (still idle,
same session id, no stop events); a test that a renew with no hold still works.

Out of scope: the `--ignore-budget` flag, changing hold policy, p4ks (a separate task).

Size: small. Model: Sonnet.
