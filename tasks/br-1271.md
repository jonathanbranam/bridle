   (replace by explicit override, append, disable with reason, a locked client rule can't be
   overridden by a game), and sibling chains are resolved SEPARATELY, never in one list (two
   siblings defining the same rule id must not hit MissingOverride). Update rules.rs's
   header comment.
5. `bridle rules explain <id> --component <id>` and `bridle rules diff ... --component <id>`
   (CLI in crates/bridle/src, plus the API/handler if rules commands go through the daemon).
   Without the flag, output is unchanged.
