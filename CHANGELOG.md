# Changelog

All notable changes to bridle are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## Unreleased

- Feature (br-btpy): `bridle project start` installs and starts the project's mail bridge on every start, not only after a take-over, when the project is in `[mail] projects` and the machine has mail set up. It prints what it did or why it skipped; a mail failure no longer fails the start and prints the `bridle mail install` command to run. Migration: none.
- Docs (br-7r2h): the orchestrator role says to keep one waiter, on its home daemon, not one per project (the startup step and Watch duty contradicted the forwarding rule). A project that does not forward to the home is named for `bridle token pair`, not given its own waiter. The aide and advisor roles say the same. Migration: none.
- Fix (br-gr3v): `bridle token pair` homes the orchestrator in its `<machine>-home` project when that machine has one (it was the same-named project, else `bridle`, else the holder's first project), and a re-pair moves existing visitors there. On the holder's own machine the orchestrator now holds a visitor token (home `<machine>-home`) on every local daemon except the home, replacing its direct one, so those daemons forward their wakes to the home and one waiter on the home daemon is enough. Migration: re-run `bridle token pair` on dalek, vesta and remus after the upgrade (it re-mints the orchestrator's tokens).
- Fix (br-b97n): `bridle projects sync` and `projects add` no longer drop a `[mail] projects` entry just because the project is not in `[projects]` yet; they add registered projects, keep every other entry on every machine, and print the names they left. Migration: none.
- Fix (br-eas4): `bridle serve --project X` run from another project's folder now refuses before anything else, naming both projects and the folder, instead of serving that repo under X's name; the "already running" refusal now names the project and workspace. Migration: none.
- Fix (br-7bs2): the macOS firewall no longer blocks the installed `bridle` after a self-upgrade or `just install`. The binary is now signed as a copy named `bridle` with `-i bridle` outside the live path and renamed into place (so `~/.cargo/bin/bridle` is never linker-signed or misnamed); the self-upgrade builds into `<state>/upgrade-root` and installs from there (so `cargo install --list` no longer tracks the self-upgraded build); the other launchd jobs running bridle (gateway, mail) restart onto the new binary; the daemon logs the binary's signature before each restart, and after start raises an incident naming the firewall if it cannot connect to its own tailnet address. Migration: none.
- Fix (br-d7r5): a restart or self-upgrade now waits for a `bridle ticket land` in progress (its check, merge, push and done), as it waits for a turn, so the land is no longer cut off; a land holds the drain for at most 2 h. Migration: none.
- Fix (br-54sp): a rejected push of the integration branch (the automatic push, and `bridle push`) re-fetches first and raises no `push.failed` alarm when `origin/<branch>` already equals or contains the local branch, as when the manager pushed the same commits first. A real rejection (local has commits origin lacks) still alarms. Migration: none.
- Fix (br-sy6z): `bridle project take-over` on the machine that released a project now says it was released by this machine and how to take it back (`bridle project start`), not "already owned". Behaviour is unchanged. Migration: none.
- Fix (br-9a7b): `bridle daemon restart --upgrade` under `self_upgrade = "release"` installs the newest release of `release_repo` newer than the running binary, as the automatic upgrade does, instead of looking for a green commit; "nothing to upgrade" then names releases. Migration: none.
- Fix (br-mfcj): the mail bridge no longer hangs for good after a stalled S3 download: each S3 list, get and delete times out after 60 s and the next poll runs, and a bridge with no successful poll for 5 x `poll_secs` exits non-zero so its unit restarts it. Migration: none; the existing units already restart on a crash, no `bridle mail install` re-run needed.
- Fix (br-257v): the mail bridge puts the content of text attachments (`text/*`) into the delivered body under an "Attachment: <name>" line, cut at 100 KB per part; images and other binary parts are still ignored. Migration: none.
- Fix (br-36a3): role tokens the database rejects now raise an incident notice naming `bridle token pair`, at start and when 401s hit three or more held role tokens within five minutes (once an hour at most). Migration: none.
- Fix (br-bc37): the mail digest lists the other tickets when one has a kind or state this build doesn't know, and a digest that can't be sent is told to the human (a note, once a day). Migration: none.

## [0.7.4] - 2026-10-15

- Fix (br-6gkv): the mail bridge routes a BCC: the project address is also read from the `for <addr>` of `Received` headers, and mail that matches no project is logged (key, from, subject) instead of skipped silently. The stuck object `inbound/lf07te0vv2hu4tvpo8e1pnaqfieg1c5b9kc8ld01` is delivered by running the bridge once after this lands. Migration: none.
- Fix (br-m38a): the mail bridge keeps forwarded mail: an inline forward ("Begin forwarded message:", "---------- Forwarded message") is no longer cut as quoted history, every inline text part is used, and an attached `message/rfc822` forward is appended to the body with its headers. Text attachments were already saved as files. Migration: none.
- Docs (br-37hz): the manager role and skill spawn workers and researchers with `--ticket <id>`, so the 10-minute settle hold (br-85hs) applies to them. Migration: none.
- Docs (br-qca7): the aide role prompt says the machine's one orchestrator lives in `<machine>-home`, to check its waiter there (`bridle status --json --project <machine>-home`), and that the aide listens only on its own daemon (replies are forwarded). Migration: none.
- Feature (br-eapt): `GET /v1/usage/sessions?since=` lists every hosted session (and external statusline session) with its start and end reason, the renewal limit in force, tokens, cost, the first turn's cost and context (startup), and peak and final context; `GET /v1/usage/sessions/{agent_id}/{session_id}/turns` gives the context size per turn. The gateway serves both (`/api/v1/usage/sessions`, `/api/v1/projects/{project}/usage/sessions/{agent_id}/{session_id}/turns`) across projects, an unreachable project listed and never counted as zero. Additive; migration: none.
- Docs (br-pmdh): the new-machine guides (`docs/context/add-a-machine.md`, the WSL2 guide) say to log in to Claude Code before the first `bridle serve`, unit start or `bridle project start`, and why (a daemon started before the login has agents that crash until it is restarted). Migration: none.
- Feature (br-f8f9): `bridle up` starts this machine's orchestrator in a tmux pane tagged `@bridle=orchestrator` if none exists (starts a detached tmux server if none runs; running it twice starts one). `~/.bridle/no-autostart` makes it start nothing. `bridle up --install` writes a launchd plist / systemd user unit that runs it at boot (prints the load commands, never runs them); `bridle up --print-tmux-hooks` prints the tmux-resurrect hooks that keep the pane tag across a restore. Opt-in; migration: none.

- Feature (br-29se): `bridle project add NAME [--machine M] [--port N]` registers a new project: writes the `[projects]` entry here (next free port above the highest if none given), then `projects sync --apply` so every machine and `[mail] projects` have it. Register only; no repo, no daemon. Migration: none.

- Fix (br-eg64): `bridle project start` (and `token pair --projects P`) re-pairs every machine's peer tokens, not only the machines that have P, and its check covers them, so after a take-over the other machines' mail to the moved project no longer queues as `invalid token` and a stale entry shows as refused. Migration: none.
- Feature (br-afzu): `bridle projects sync` spreads `[mail]` too, with `projects` derived (`bridle` first, then every `[projects]` name), so every project takes mail on every machine. `[machine] mail = false` (never synced) turns mail off on one machine: `project start` skips the bridge, `mail install` refuses, `project preflight --to` skips the AWS check. Mail on without AWS credentials: `project start` skips the bridge with a warning and `bridle doctor` warns once. Migration: run `bridle projects sync --apply` once.
- Feature (br-85hs): the 10-minute hold covers all work on a ticket. `[tasks] settle` defaults to 10m (was 5m; projects without the key get the new default, bridle's own config already had it), and claiming, planning and spawning an agent for a ticket (new `bridle agent spawn --ticket <id>`) are refused with `settling until <time>` in any state, pending included. A comment relaying the human's words ("From the human ..." or "human via <agent>", a text match) restarts the clock like the human's own. The human's own plan and spawn are not held; `skip-settle` is unchanged. Migration: none.
- Fix (br-tcae): the mail bridge restarts onto a new `bridle` binary by itself (a `just install` or either self-upgrade), instead of running the old one for days, and the daily digest is still sent when the task list holds a ticket kind or state the bridge doesn't know. Migration: none; re-run nothing, but restart each mail unit once to get the new watcher.

## [0.7.3] - 2026-10-14

- Feature (br-cvfu): `bridle daemon restart --cancel` ends a pending drain (a restart or self-upgrade waiting for its quiet point) and `--postpone <dur>` (e.g. `30m`) holds off restarts, self-upgrades and a pending drain's quiet point, so a `bridle ticket land` is not killed mid-check (br-8swr); `bridle status` shows the postponement. Allowed to the human, the orchestrator and managers. Migration: none.
- Fix (br-8usa): `bridle token pair` re-mints a visitor token whose recorded home differs from the home it would get now (an orchestrator that moved to `<host>-home`), so mail forwards to the new home; it kept any token that had a home. Migration: run `bridle token pair`.
- Feature (br-qwd4): `bridle project preflight --to M --path <clone path on M>` names the clone's path on the new machine (`~` is M's home); the clone check, the `git clone` offer and the git push probe use it. Without it a project outside `$HOME` defaults to `~/work/<project>-workspace/<project>` instead of copying OLD's absolute path. Migration: none.
- Fix (br-82qp): `bridle schedule list` also shows schedules others set that target the caller (it listed only ones the caller created, so an aide could not see the schedule that wakes it). Each entry carries `relation` (`created` or `target`), and the table adds "(set by X)" for the latter. `schedule rm` is unchanged (creator or human). Migration: none.
- Fix (br-g9qm): `bridle token pair` makes the peer tokens before the role tokens, and with `--projects P` still makes the peer entries a machine needs to forward to projects outside P, so `bridle project start` on a machine's first project ends with failed 0 (the visitor-token mint needs `[peer]` entries the run made only afterwards, or never). The daemon's "no peer token" error now says to run `bridle token pair --tokens peer`. Migration: none.
- Fix (br-x8c8): mail to a visitor (`external:<name>@<machine>`) whose recorded home is this daemon's own project is refused with an error instead of being forwarded back to the local principal of the same name. Moving a visitor's home on re-pair is not done yet (follow-up). Migration: none.
- Docs (br-yp8f): `docs/context/add-a-machine.md` has a "Remote PATH" step (which commands run bridle over ssh, the system zshenv lines for macOS and Ubuntu/WSL2, and the `ssh <host> 'command -v bridle'` check), and the WSL2 guide says its `export` fixes only the interactive shell. Migration: none.
- Fix (br-kf7t): `bridle project start` works on a brand-new project (no `bridle/state` locally or on origin): the daemon it starts creates the branch and claims this machine as owner, so the `bridle serve` workaround is gone. It still refuses when origin has an owner other than this machine or can't be reached. `take-over` on such a project says "new project: run `bridle project start`" instead of "origin unreachable"; a startup fetch now tells an absent branch from an unreachable origin with `ls-remote`. Migration: none.
- Feature (br-su62): `bridle token check [--machines] [--projects] [--roles] [--tokens] [--json]` tries every token entry from the machine that holds it against the daemon it is for and prints accepted or refused (with the reason) per machine, role and project; non-zero on any refusal. It is read-only. `bridle token pair` now ends with the same check over what it paired and exits non-zero if any entry is refused, and uses the same code to decide keep or re-mint. Migration: none.
- Fix (br-pcde): `bridle mail run` decides ownership with the daemon's own `owner_names` (`[machine] name`, then `hostname`) instead of the raw `hostname`, so a machine whose name differs from its hostname (dalek vs dalek.local) takes its project's inbound mail again; mail left waiting is delivered on the next poll after a bridge restart. Migration: none.
- Docs (br-8uxe): the orchestrator runs in its machine's home project, `<host>-home` (dalek-home, vesta-home, remus-home), and senders address `--project <host>-home`; the orchestrator role, the advisor, aide and manager role notes, the PdM trial notes and `docs/context/add-a-machine.md` (new "The home project" step) say so, with bridle as the home until a machine has its own. Migration: none; workflow files reach projects with `bridle workflow update`.
- Fix (br-sh8y): commands that run bridle on another machine over ssh (`token pair`, `project stop|start --machine`, `project preflight --to`) also look in `~/.local/bin` and `~/.cargo/bin`, and say "bridle not found on <host>" (shell exit 127) or "<host> unreachable" (ssh exit 255) instead of a bare shell error; preflight shows where bridle was found. Migration: none.
- Fix (br-xcb4): `bridle daemon rebuild` no longer fails with `malformed thread` on tickets whose comments contain `##`/`###` headings (only an exact entry-header line starts a thread entry), and a parse failure now names the file, line and line text; rebuild reports every bad file at once. Migration: none.
- Fix (br-j4bk): the integration `target/` is pruned after each warm build once `debug/deps` passes 100,000 entries, and `warm_target` skips cloning a source that large, so a bloated target no longer stalls spawns, lands and self-upgrades. Migration: none.
- Fix (br-nncj): a daemon no longer forwards its wakes (restarts, exits, usage, context, uptime) to a visiting orchestrator homed on another machine when it has an orchestrator of its own; before, dalek's wakes also reached vesta's orchestrator. Migration: none.
- `bridle project take-over` no longer moves the database out from under a running daemon (which went on minting tokens into the moved file and lost them all at its next restart); it refuses and says to stop the daemon first. A daemon that starts with role tokens in `credentials.toml` that its database rejects logs a warning naming `bridle token pair` (br-nbgp).

## [0.7.2] - 2026-10-14

- `bridle usage --week` prints the current week from the reset (days, five-hour windows, peaks, hits), and `bridle usage --by name|session` the role -> name -> session cost tree with share-of-week estimates, hosted and external together; both take `--json` (br-v58q).
- New gateway route `GET /api/v1/usage/account?since=&until=`: usage summed over every project the gateway reaches, by role -> name -> session with project and machine, shares re-estimated over the account, the weeks, days and five-hour windows once (account-wide), and unreachable projects listed, never counted as zero; TS bindings added (br-v6cg). Migration: none.
- Budget pacing and sprint (br-dtf6): the governor sends the human and the orchestrator one note a day when `seven_day` is more than `[budget] pace_margin` (default 10) points over the day's pace line (day x 1/7 of the week, counted from the reset); it holds nothing. A `[[budget.schedule]]` period can now also set `seven_day`, `seven_day_opus` and `seven_day_sonnet` thresholds (an end-of-week sprint) and its `max_workers` applies while it matches by the clock. Migration: none (new optional keys).
- `bridle statusline` now counts Claude Code sessions run outside any bridle project: they report to one daemon per machine (the first live project by name) as `external:unbridled/outside any project`, shown in that project's `bridle usage` external sessions (br-drvx). Migration: none.
- New `GET /v1/usage/groups?since=&until=`: a period's cost, tokens and context growth grouped role -> name -> session, hosted and external together, each row labelled with project and machine, with each group's share of the period's seven_day points (an estimate: cost share x points gained) and the measured points per dollar (br-zn6s). Migration: none.
- `bridle project start` now re-creates the project's missing tokens on every run (before, only right after a `take-over`, so a fresh database left the orchestrator and aides with 401s), printing minted/kept per machine; an unreachable machine fails the start naming it and the `bridle token pair --projects <p>` command to finish. The ssh calls in `token pair` and the remote preflight now time out (connect 10 s, 60 s in all) instead of hanging on Tailscale SSH check mode.
- Each hosted session is now recorded (`agent_sessions`): how it started (spawn, resume, renewal), how it ended and at what context size, and the renewal limit in force, so context limits can be compared by cost (br-2kam). Migration: automatic (one new table, no backfill).
- Usage periods group readings whose `resets_at` differ by milliseconds (or across a minute edge) into one five-hour window or week, instead of one per distinct value; `GET /v1/usage/periods` now lists the real windows and weeks (br-bm7a). Migration: none.
- `bridle token pair --rotate` now replaces peer tokens that already exist (before, every one failed with "peer:<machine> already exists"); the receiver swaps the token in one step, so the old one stops working as the new one is minted (br-xqwy). Migration: none.
- `project take-over` no longer deadlocks after a host rename: a local integration branch that is ahead of origin (commits the pre-push hook held back) is accepted and pushed once the claim is on origin; only real divergence is refused, and the message says so. The ssh calls that move `[projects]` time out (10 s connect, 60 s overall) and name the machine instead of hanging on Tailscale SSH check mode (br-wfcx). Migration: none; after renaming a machine, run `take-over` in every project.
- The orchestrator's usage wake fires once per crossing: a reading jittering around the limit (84.9%/85%) no longer re-wakes every poll; it re-arms after a fall 3 points below the limit or a new window (br-63nr). Migration: none.
- Each turn in the ledger records the Claude session it ran in and its context size (`turns.session_id`, `turns.context_tokens`), so a renewed agent's history splits into sessions (br-pac3). Migration: automatic; old turns stay NULL.
- `GET /v1/usage/periods` lists the weeks (from the seven_day reset), their days and each real five-hour window with its peak and whether it hit the limit, so "did we hit a five-hour limit last week?" has an answer (br-pemk). Migration: none.
- An external session's first statusline report counts in full when its running totals are small (under $1 and 100,000 tokens), so a new session's startup cost shows; a larger first total (a resumed session) is still a baseline (br-mksa). Migration: none.
- The web UI session cookie is re-issued with a fresh 30-day `Max-Age` when the session slides (at most hourly), so a daily-used login no longer drops 30 days after the first login (br-ry8z). Migration: none.
- The web UI login survives a gateway restart or reboot: sessions are kept on disk (`<bridle home>/gateway-sessions.json`, hashed, mode 0600) and last 30 days, sliding, instead of 12 hours in memory (br-v56p). Migration: none; everyone logs in once after the upgrade.
- `bridle ticket ready` files the row of a ticket file that has none, prefers a pending row over a dropped duplicate, and the daemon strips its own prefix from a qualified `ticket` on `POST /v1/tasks` (no more `br-br-xxxx`) (br-w8jm). Migration: none.

A test pins that another identity's wait does not count as the orchestrator's waiter. Migration: none.

Migration: none.
- The per-instance usage list and series now include external sessions (br-njjt): one `external` instance per identity, charted from the statusline reports; `turns` and busy time are null for them, and `bridle usage --agent external:advisor` works.
## [0.7.0] - 2026-10-12
- Usage of one agent instance over time (br-xfy7): `bridle usage --agent <name|id> --since 7d [--bucket hour|day]` prints its turns, tokens, cost and busy time per bucket, removed agents included. New daemon routes `GET /v1/usage/agents` (instances with usage) and `GET /v1/usage/agents/{id}/series`, proxied by the gateway under `/api/v1/projects/{project}/usage/agents`. Migration: none.
- `bridle usage` now counts the orchestrator, advisors, aide and the human's own Claude Code sessions as external sessions (cost and tokens per session identity, with `--by` and `--since`), from the statusline's per-session running totals; a session that reports nothing shows "not measured", not zero. Existing projects need nothing but the new binary (daemon migration 28).
- Usage no longer shows negative costs for long-running agents (br-9y7v): a renewed (or fresh-session) agent's cost counter restarts at 0, but the turn's cost delta was taken against the agent's lifetime total, so the first turn after a renew recorded a large negative cost. The baseline is now the claude session's own last total (new `agents.session_cost_usd`), and a delta is never negative. Migration 27 zeroes existing negative turn costs and re-sums those agents' lifetime totals.
- Gateway: `GET /api/v1/projects/{project}/usage/history?window=&since=` serves the daemon's rate-limit history (br-yydm, the gateway half of the usage charts; the page is a bridle-ui ticket). Migration: none.
- The project drain's hold survives a daemon restart (br-yt5v, kx5u K4 follow-up): `bridle project drain` now stores the hold in the database and the daemon restores it at start; only `drain --undo` lifts it. Migration: none (absent means no hold).
- Docs: the runbook for moving a project by hand, `docs/context/move-a-project.md` (br-ep5z, kx5u K10): preflight, drain, stop, take-over, start, checks and back-out at each step.
- `bridle project stop` closes the old machine for good (br-3vv3, kx5u K5): after the released mark and the unit unload it adds the clone to `[machine] tools_only` (so `bridle serve` refuses it there), removes the registry entry and the `upgrade-*` worktree and build tree, and says `bridle.db` stays. A second run changes nothing. `project take-over` on a machine that held the project before removes that `tools_only` entry, so `bridle serve` works there again. Migration: none.
- Return trip (br-d6h6, kx5u K9): `project take-over` moves a database left from an earlier stay to `<workspace>/.bridle/db-backups/<date>-<sha>/` (with `-wal`/`-shm`; kept, not in git) so the daemon builds a fresh one, and seeds the fresh outbox counter above the old database's and above the `outbox-seq` file `project stop` now commits with the released mark, so receivers do not drop new mail as duplicates. A release without `outbox-seq` still works (seeds from the old database only). Migration: none.
- `bridle project drain [--undo] [--repo PATH] [--leave PATH]` (br-kefh, kx5u K4), the step before `project stop`: holds new claims and spawns for this project's daemon only (running agents carry on), announces the move to every running agent and registered session, then waits with no timeout until the stable-project check passes, messaging the orchestrator at the start and on each change and naming a drain unchanged for 30 minutes to it and to aide. `--undo` lifts the hold. New `POST /v1/project/hold` and `held` in the status. Migration: none.
- `bridle project stop` refuses unless the project is stable (br-mzy4, kx5u K3); `project preflight` gains the same "stable project" check: no claimed or built ticket, no running agent, no `bridle/*` or `integrate/*` branch ahead of the integration branch, integration branch on origin, clean main checkout (`--leave PATH` lets a path through, listed as LEFT), no undelivered mail. Each failure is named. Migration: none.
- `bridle project start` moves the mail bridge too (br-3v2m, kx5u K6): when `[mail] projects` names the project, it copies the old owner's `[mail]` section and `mail.key` (0600, over ssh) if missing here, installs and starts the bridge unit. Without a key to copy it says replies to mail sent from the old machine will fail verification. Projects with no `[mail]` entry move as before. Migration: none.
- `bridle-grill` asks first how the human will answer (br-bs85): mobile, computer or voice. Voice gets exactly one short question per round; mobile keeps the two-question limit but short; computer as before. Migration: none.
- `bridle projects preflight --to MACHINE` (br-bb2n, kx5u K2): also checks the new machine over ssh before a move: bridle version, claude and gh logins, git push access, toolchain, tmux, `[machine] name`, host name, timezone, AWS (when `[mail]`), WSL systemd and linger, the clone (asks before cloning) and the `projects sync` comparison; each failure says what to run there.
- `bridle project preflight` (br-3ch7, kx5u K1): read-only checks before a project move; the first refuses an absolute or `~` `workflow` / `system_prompt` in `.bridle/config.toml`, naming file, line and key. `bridle doctor` warns on the same ("portable paths"). No automatic rewrite: fix by hand. Migration: bridle-ui, track-web and data-contracts need their config fixed before they move.
- Orchestrator cross-check and recovery mode (br-10c0): the daemon compares the orchestrator pid file with the wake polls it sees. A dead pid with a poll open, or two polls open, is a disagreement: it does not relaunch, and messages `external:orchestrator` to confirm its pid. Still unsettled after 5 minutes: an incident, and recovery mode (a flag file `$BRIDLE_HOME/orchestrator.recovery`: no relaunch, no context/uptime notes) until `bridle orchestrator clear-recovery`. The launcher's refusal under a bridle agent already existed (k6b3). Migration: none.
- `bridle-grill` skill (br-mtph, from br-k9j4): interviews the human to clarify a ticket or epic, one or two questions at a time with the open count, asks "epic or ticket?" first, records answers on the ticket thread and the settled result in its body, checks a child against its parent epic, and never readies, plans or builds. Adapted from Matt Pocock's `grilling` (MIT, credit in the file). Not wired into any role yet. Migration: none; reaches projects with the workflow update.
- A handover request no longer reaches the new session (br-ve74): when an external session writes its handover note, its unread restart request and context-limit notes are marked read, so the next session is not told to hand over what it never had. Migration: none.
- `bridle project start` (br-86qp, part of br-53gy): step 4 of a move. Installs the project's launchd or systemd unit if missing, enables it (boot, restart on failure) and starts it, waits for the daemon, then re-creates the project's tokens on every machine with `token pair`'s code and re-adds its scheduled messages. `project stop` now commits the active scheduled messages to `bridle/state` as `schedules.json`; `take-over` notes them for `start`. `--machine M` runs it over ssh. Migration: none; a stop by an older bridle carries no schedules, so recreate those by hand.

### Fixed

- `bridle budget --help` (and any `bridle budget` parse) no longer panics on a clap debug assert for a non-existent `conflicts_with = "action"` attribute; added tests for `--help` on budget and related subcommands to catch this class of bug.
- Help text for `bridle statusline`, `bridle prime`, `bridle task` and `bridle usage --by` now accurately reflect their supported roles and options.
- `bridle land` no longer leaves a worktree that has the integration branch checked out (the clone) showing the new tip as staged changes: it fast-forwards there (`merge --ff-only`) instead of `update-ref`, and refuses if that worktree has uncommitted changes (br-land).
- After a budget pause the governor resumes the manager and PM along with workers; `max_workers` limits workers only (ticket k7nr, br-0a50; code landed with y2eb).
- A resumed agent whose Claude Code session is gone no longer dies on its first turn on every resume; the daemon retries once on a fresh session in the same worktree, and `agent.exited` carries the claude `stderr_tail` (ticket p4ks, br-3ec1).
- `bridle renew` no longer waits on a budget hold (it replaces a session rather than adding load), so a hold can't leave the agent stopped; `--ignore-budget` is accepted and ignored on renew (ticket r3nh, br-1392).
- `bridle sync` no longer creates an empty `.claude/settings.json` when there are no hooks to write (br-082f).
- Dropping a claimed task now releases its claim, the claim lease check never moves a task that isn't `claimed`, and the daemon discards claims on non-`claimed` tasks when it loads, so a dropped task no longer lingers under "Claimed" in `bridle queue` (ticket b5br).
- Lists of tasks, edges, claims, open questions, agents and tokens now break `created_at` ties by insertion order, so rows created in the same millisecond no longer come back in either order; fixes a flaky components test (ticket f1ky).
- On Intel Macs (x86_64), `.cargo/config.toml` now ad-hoc code-signs binaries at link time, preventing crashes in macOS's system policy daemon when executing unsigned Mach-O binaries; the flag is a no-op on arm64 (ticket cs7x).
- TUI agents panel and inbox now scroll to keep the selected row visible (tickets yurx, 8ups, br-9e67).
- TUI agents and inbox lists no longer lose the highlight on the selected row (regression from making them scroll) (br-ee7d).
- TUI now shows agents spawned after it started: an event for an agent it has no row for triggers a refetch of the agents list, keeping the selected agent selected (ticket n4vk, br-ee7d).
- `bridle renew` under a budget hold refused only after stopping the agent, leaving it stopped; the hold check now comes first, so a refused renew changes nothing (ticket r3nh).
- An agent renewed and then resumed after a daemon restart before its new session's first turn died on its first turn (`--resume` of a session claude never wrote); `resume` now starts a fresh session in that case (`agents.session_started`, schema v13), and an abnormal claude exit is logged at warn with its stderr tail.
- Autostart now skips a role that already has an agent of that role (any state), not only one named after the role, so a restart no longer spawns a second manager beside e.g. `manager-2` (br-ee7d).
- Daemon shutdown no longer hangs while a client (`bridle tui`, `events --follow`) holds the event stream open; the stream now ends when shutdown begins, and the HTTP drain is bounded at 5s.
