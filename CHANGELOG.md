# Changelog

All notable changes to bridle are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## Unreleased

### Added
- `triage` role and `bridle session triage` / `bridle prime triage`: the session that talks with the human about the running system (their to-dos, the workforce's questions, status), relays their answers to the orchestrator, and files tickets. The orchestrator no longer talks with the human: it reaches them only by messaging `external:triage`. The advisor only talks, researches and files tickets, and its opening prompt no longer asks for a status check-in. Needs a `[triage]` token in `credentials.toml` (`bridle token create triage`).
- The gateway serves the human-time reports: `/api/v1/interactions/report` (per project, agent or machine; per day or week), `day` (timeline, overlaps, concurrency), `hours` (minutes per hour of day, filterable by weekday) and `intervals`, with days split at US Eastern midnight (br-59vt, u6w9).
- The gateway collects the human's interactions every 5 minutes from every daemon it knows (prompt logs and messages from the human) into its own store, and computes per-session intervals, human time and concurrency from them; `[interactions] gap`, `tail`, `lead` in the config (br-25nn, u6w9).
- `GET /v1/interactions?since=` serves the machine's prompt log (human and local readers), and `bridle focus reply`, a `Stop` hook in `bridle session`'s settings, logs when an agent finishes replying (`event: reply`; prompt lines get `event: prompt`); the gateway's human-time API types are generated for the UI (br-bhcp, u6w9).

### Changed
- `bridle ticket new` no longer files a task (br-6c69, k7tm): the task raced the ticket's commit. `bridle ticket task <id>` files it once the ticket is committed on `main` with a non-empty ask; `ticket new --body`/`--body-file` write the ask; `--no-task` is a hidden no-op.
- One id space for tickets and tasks (br-9e15, k7tm): new task ids use the ticket alphabet (`abcdefghjkmnpqrstuvwxyz23456789`) instead of hex; a ticket's first task takes the ticket's id (`br-k7tm`), later ones get fresh ids; `bridle ticket new` never mints an id a task already has. Existing task ids are unchanged; no migration.
- Fresh warm-build source (br-14cd, b7cz step 2): new `[integration] warm_build` (unset by default; this repo sets `cargo build --workspace --all-targets`) runs after each successful land, niced and in the background, in the integration worktree: one at a time, a landing during a build queues one more, failures only logged. `[worktrees] warm_target` now copies the integration worktree's `target/` when it exists and its build is idle (or newer than the clone's), else the clone's, and logs the source and its age. No migration.
- Self-upgrade wakes only on what needs attention (br-e5f1, p372): skipped (docs-only) and building no longer wake the orchestrator; every step is an `upgrade.*` event (`bridle events --kind upgrade.`: skipped, building, built, waiting, gave_up, failed, rolled_back). For the automatic upgrade, "no quiet point" is now silent and retried on later ticks, with one `upgrade_failed` wake (no human note) after three hours; real failures still wake and note the human. No migration.
- Layer hooks reach every spawned agent (br-01a4, 34bw step 3): at spawn the daemon resolves each layer's `hooks/<event>.json` (base, packs, project: the overlay `bridle sync` uses) and merges it into the `--settings` hooks, so e.g. `bridle arch-guard` is live without `bridle sync` or committed `.claude/settings.json`. Arrays concatenate with bridle's `Stop` check first; bad hook files are skipped with a warning; entries already in the committed settings are not doubled. No migration.
- Task watchers 3/3 (br-7605, xxxq): a task change is now a message, not a wake reason. For each change (comment, question asked or answered, priority, kind, state) the daemon sends every watcher except the actor one `task_update` message, one line: `<id> (<title>): <change>`, e.g. `br-1 (x): open -> planned by human`, `comment by human: <first 200 chars>`, `question asked by agent:w: <text>`, `priority normal -> high by human`. Each change is its own message; the unread message rings the wake and the agent reads the text on receipt. `GET /v1/wake` no longer returns `task` reasons (the `task` / `event` fields stay for old clients); the created-or-claimed rule and its 1,000,000-event scan are gone. Task events now also carry `from` (state, priority, kind) and `text` (comment, question, answer). New `MessageKind::TaskUpdate` (`task_update`); an unknown kind now deserializes as `note`. No migration.
- Role prompts (`workflow/base/roles/`: worker, manager, product-manager) no longer repeat summaries of rules the role's resolved rules already carry (br-899d, 34bw step 2); only the procedure and role-specific details stay.

### Fixed
- Small workflow breaks (br-66a0, 5u9d): a git-url `workflow` is now a config error (`WorkflowGitUrl`) where a missing directory already was (`serve`, `sync`, `prime`, `rules`, `doctor`), not a silent empty base layer; `init --stack rust` is no longer accepted (there is no rust pack) and `init` no longer suggests it from `Cargo.toml`; stale lines in `sync.rs`, `workflow-layers.md` and the `work-flow` / `cost-of-not-doing` rules corrected.

### Added
- Spawned agents get their role's resolved workflow rules (base, packs, project; no components) in the system prompt under `## Workflow rules`, the same list `bridle prime` prints (br-2242, 34bw step 1; one shared `rules::rules_section`). Identical for every agent of a role; unresolvable rules are skipped with a warning and never fail a spawn. `bridle cost audit` measures the larger prompt.
- Task watchers (br-eb50, xxxq 2/4): a task has a `watchers` list of principals, in the API/JSON, `bridle task show` and the task file's frontmatter (written even when empty; `bridle rebuild` restores it). The creator is added at creation and the claimer at claim; `bridle task watch <id>` / `unwatch <id>` add and remove the calling principal (`POST /v1/tasks/{id}/watch|unwatch`), recorded in the thread and as a `task.watching` event only when the list changed. `tasks::notified_of(task)` answers who is told of a change, for the notification work (br-7605); nothing is delivered yet and wakes are unchanged. Existing tasks are backfilled at start-up (a file with no watchers record gets its creator and current claimer, once); a failure logs and never fails start-up. No SQLite change.
- Read on receipt (br-ee78, rmpq): a message that reaches an agent's context is read, with no mark-read step. A headless agent's message is `read` at the stdin ack; `bridle agent wake` returns the messages in full (`messages` on the reason) and marks them read in the same store call, so a second wake doesn't repeat them; the orchestrator's `wait-for-wake` marks its `message` wakes read as it answers; `bridle inbox` / `inbox show` by an agent or external principal mark what they list read (`mark_read` and `id` on `GET /v1/messages`). Only the human can `inbox unread` (others get 403); the human's reads stay explicit. `--mark-read` still works; the advisor prompt no longer asks for it. No migration. Overlaps br-2672 (orchestrator wakes): whichever lands second reconciles.
- Task creator (br-c078, xxxq 2/4): tasks carry `created_by` (the creating principal), set at creation, shown by `bridle task show`, in the API/JSON and in the task file's frontmatter, so `bridle rebuild` restores it. New nullable `tasks.created_by` column (SCHEMA_V19), backfilled at start-up from each task's earliest `task.created` event's actor; a task with no such event takes the first thread entry's author from its task file, else `unknown`. A failed backfill logs and leaves the task unknown; it never fails start-up.
- Serve login warning (br-faf5, nrbf): `bridle serve` runs `claude auth status` off the start-up path (5 s limit) and logs a loud warning with the fix when claude isn't logged in; a missing claude, timeout or error is "unknown" and silent, and never delays or fails start-up.
- Not-logged-in agents (br-5b39, nrbf): a turn whose result is claude's "Not logged in · Please run /login" now ends the agent as `crashed` (reason "claude is not logged in in this daemon's session", a crash wake) instead of recording a successful turn and idling; `bridle doctor` runs `claude auth status` and fails loudly when logged out, with the fix (start the daemon from a local terminal or tmux, not over SSH). No start-up check yet.
- Settle wake (br-96cc, ny9u): when a planned task's settle period ends, the daemon notes the running manager (else the orchestrator) "<id> is now startable", once, from a 30 s tick with in-memory state only; dependency-blocked and already-settled tasks make no note. No schema change.
- Wake timeouts (br-c4f4, 789x): `bridle agent wake --timeout` and `GET /v1/wake` accept up to 6900 s (1 h 55 min, under Claude Code's 2-hour background-task kill) and clamp above; `bridle orchestrator wait-for-wake` (and `--mail`) gets `--timeout` with the same cap (default still 25 min), and `GET /v1/orchestrator/wake` a `timeout_secs` parameter. The advisor role waits `--timeout 5400` as a fallback only.
- Gateway actions (br-55f6, essy 4/10): `POST /api/v1/projects/{project}/tasks/{id}/{done|drop|answer}` checks off a to-do, declines one (body `{"text": reason}`) or answers a task question (`{"text": answer}`) on that project's daemon, with the human's token found the way the CLI finds it. Any other action is refused (404); a missing token is a clear 503; this machine's projects only. No daemon change; nothing to migrate.
- Gateway hides withdrawn items (br-a913, essy 5/10): a dropped to-do and a question on a dropped task no longer appear in `GET /api/v1/items`; the daemon keeps the withdrawal and its reason on the record. Tasks have no separate retracted-question state, so only dropped is hidden.
- Gateway items (br-ec04, essy 3/10): `GET /api/v1/items` returns the human's to-dos (tasks claimed by `human`) and open task questions from every reachable project, grouped by project (projects with decisions first), each list high priority then oldest; projects that don't answer are listed under `unreachable` with a reason. No daemon change; nothing to migrate.
- Gateway serves the UI (br-fa63, essy 8/10): files from `[gateway] ui_dir` (default `~/.bridle/ui/`) at `/`, index fallback, no directory traversal, open so the login page can load. The folder's `api-version` file is compared with the gateway's API version: `ui_version_mismatch = "warn"` (default) logs and reports it in `GET /api/v1/health`'s new `ui` field, `"refuse"` answers 503 at `/`. A missing folder gets a plain message at `/`; the API still works. New optional config; nothing to migrate.
- Gateway TypeScript types (br-8545, essy 7/10): the gateway's request and response types derive ts-rs `TS` and are committed under `crates/bridle-gateway/bindings/` for `bridle-ui`; `just gateway-types` regenerates them and a test fails when they are stale. `API_VERSION` records the API version for the UI version check. No daemon change; nothing to migrate.
- Gateway login (br-9418, essy 6/10): `[gateway] username` and `password_hash` (an argon2 hash from the new `bridle gateway hash-password`, which reads the password on stdin) turn on `POST /api/v1/login` and `/logout`, with an `HttpOnly`, `SameSite=Strict` session cookie held in memory (12 hours). Every `/api/v1` route except health now needs that session; with no login configured the gateway answers health only. New optional config; nothing to migrate.
- Gateway discovery and fan-out (br-c601, essy 2/10): `GET /api/v1/projects` lists every project the gateway's machine knows (the `~/.bridle/daemons/` registry, `[projects]` and `[machines]` of `config.toml`) with its machine and whether its daemon answered `/v1/health` within 2 s. A daemon that is down, slow, or misconfigured is listed `reachable: false` with a reason, not an error. No daemon change; nothing to migrate.
- `bridle gateway` (br-1e88, essy 1/10): the skeleton of the human web UI's gateway, a new `bridle-gateway` crate. It serves `GET /api/v1/health` on the optional `[gateway] bind` of `~/.bridle/config.toml` (default `127.0.0.1:7878`; `0.0.0.0` is refused unless `allow_any_interface = true`). Only `bridle gateway` reads that section, so a bad one fails there alone. No daemon change; nothing to migrate.
- A `prototyper` role in the base workflow (br-a4ea, 6yb4): build a prototype only from the prompt's constraints (read what a constraint names, ignore the rest, rethink the design when asked, make several prototypes genuinely differ, ask where it lives if the prompt doesn't say). `bridle spawn prototyper`, `bridle prime prototyper`; a project's `.bridle/roles/prototyper.md` is appended. Instructions only, no sandbox. Every project inherits it; nothing to migrate.
- A settle period before work starts (br-3c71, ny9u): every task waits `[tasks] settle` (default 5m, `0` off) after creation, or after a human comment or edit, before it can be claimed or shown ready; `task show`/`task queue` print `settling until 10:42 AM` and JSON gets `settle_until`. `bridle task skip-settle <id> --reason` skips it, recorded (human; orchestrator/PM with a reason). An invalid `settle` warns, uses 5m and shows in `bridle doctor`. No schema change; old tasks are already settled.
- Overnight periods say `+1d` (br-1c2a, r5s3): a `[[focus]]` or `[[budget.schedule]]` end may be written `HH:MM+1d`, that time on the day after the start day. `bridle daemon doctor` now checks `~/.bridle/config.toml` and fails any block whose end is before its start without `+1d`, naming the block and the fix; `00:00` as an end needs none. The daemon stays lenient (it only logs a warning and keeps the next-day meaning), so nothing breaks meanwhile. Migration: a block like budget `night` 23:00–08:00 should be written `end = "08:00+1d"`; edit your own `~/.bridle/config.toml` and let `bridle daemon doctor` name any that remain.
- Advisor prime text now instructs advisors to wait for messages using `bridle agent wake` in a responsive loop with a sensible timeout (jttf 2, br-c877): unnamed advisors use `bridle agent wake external:advisor --timeout 300`, named advisors use `bridle agent wake external:advisor/$BRIDLE_ADVISOR_NAME --timeout 300`, and advisors read and mark messages read with `bridle inbox --json --mark-read` to prevent re-firing, act on what they find, then loop. Error handling degrades gracefully: if `bridle agent wake` errors (no daemon, daemon down), advisors tell the human once and back off, never spinning. Migration note: projects with `.bridle/roles/advisor.md` inherit the base role by appending; projects' own advisors will pick up the wake loop automatically.
- `bridle agent wake` has a second reason, `task` (jttf 2): since the call started, someone else commented on, asked or answered a question on, re-prioritised, re-kinded or changed the state of a task the principal created or claimed. The reason carries `task` and `event` (the event kind) and can come back alongside `message`.
- `bridle ticket submit -k <kind> <title> [--body-file -]` (93xm; `POST /v1/tasks/submit`): any principal with a token, visitors included, files an open task marked `submitted by <principal>`; the product manager (else the orchestrator) gets one message, and dropping it with a reason tells the submitter. Visitors can no longer plan, claim, drop or edit tasks.
- `bridle agent wake <identifier> [--timeout SECS]` (jttf, slice C1; `GET /v1/wake`): blocks until the daemon decides that principal should wake, then prints the reason and message ids (`--json`); exit 4 on timeout, 403 unless the caller is that principal or the human. The decision is one daemon function, `wake_reasons`, so later reasons are added there; the first is an unread message. `wait-for-wake` is unchanged.
- Named advisors are addressable (jttf, slice B): `bridle send external:advisor/<name>` (and `/<name>@<machine>`). A running session gets it in its own inbox; an ended or unknown one goes to `external:advisor` marked "(originally for advisor/<name>)" and `bridle send` says "<name> isn't running; delivered to advisor"; unread mail moves there, marked, when the session ends. A named advisor's CLI sends as `external:advisor/<name>` (from `BRIDLE_ADVISOR_NAME`, via the `x-bridle-advisor` header; a label, not proof), so replies return to it.
- Advisor sessions tag their tmux pane with their identifier (advisor or advisor-<name>) at startup using shared pane tagging code (jttf 4). Tagging is best-effort: if outside tmux or tmux is unavailable, it silently succeeds and never stops the session. The daemon can use the tagged pane to find advisor sessions.
- Advisor sessions register with the daemon (jttf, slice A): `bridle session advisor` calls `POST /v1/sessions` at launch and `/v1/sessions/end` at exit (best effort), a SessionStart hook adds the Claude session id, and the daemon reads each session's context file and emits `session.context` at the orchestrator's token thresholds. `bridle status` shows a `session` line per advisor with its tokens; ended when its pid is gone.
- Tickets get a `kind:` and a `tasks:` list (v3dk, slice A): `bridle ticket new` requires `--kind` (no default; the task gets the same kind and its id lands in the ticket's `tasks:`), `bridle ticket set <id> kind <kind>` edits it, and `bridle task kind <id> <kind>` (`POST /v1/tasks/{id}/kind`, `task.kind` event) changes a task's kind only while it is `open`. `bridle ticket check` fails an unknown kind or a one-sided ticket/task link (task side checked when the daemon is up); a missing kind or link is only a warning until the backfill migration.
- `bridle migrate [--dry-run] [--project NAME | --all]` applies the project migrations this bridle ships that a project hasn't had yet, each once and in order (xebc). Applied ids live in the project's `.bridle/migrations.toml`, with an append-only `.bridle/migrations.log` and a `project.migrated` event (new `POST /v1/migrations`) when the daemon is up. Never runs automatically; ships one no-op `0000-baseline`.
- `bridle completions <zsh|bash|fish|elvish|powershell>` prints the shell completion script generated from the clap definition, so it never drifts from the CLI. Static completions only (subcommands, flags, enum values). Install once with `bridle completions zsh > ~/.zfunc/_bridle` or `bridle completions bash > ~/.local/share/bash-completion/completions/bridle` (6rh7).
- The `bridle focus gate` hook records each prompt to `~/.bridle/prompts.jsonl` (u6w9, collection only): one JSON line per prompt in interactive sessions with timestamp (RFC3339 UTC), session id, role, machine hostname, and project name. Failures are silent; the gate output is unchanged. Reports are a later task.

### Changed
- The daemon no longer wakes the orchestrator when every agent has been idle 15 minutes (the `all_idle` wake is removed); the orchestrator picks a shorter wait timeout when it wants a check (br-6c6a, aqtg).
- Focus hours and `[[budget.schedule]]`: a period belongs to the day it starts (br-14d6, 3xr4). A period with `end < start` now also matches the morning after its start day, e.g. a `sun` 23:00-07:00 period covers Monday morning even if `mon` is not listed; this applies to `[[budget.schedule]]` too. 00:00-bounded split periods mean the same as before. The end reported by the focus gate, "locked until" and the advisor refusal is now when quiet actually ends, following periods that touch or overlap (capped at 7 days). Update your own `~/.bridle/config.toml` if you want one overnight block instead of two.
- Quiet hours gate text is now firm and measurable (cdez): at most 3 sentences or 60 words, the first a nudge back to work, no extra tool calls, research, tickets or planning, extras deferred with "saved for <end> ET". Advisor and orchestrator role text point at it. Locked mode and projects without `[[focus]]` are unchanged.
- `bridle send <bare-role>` now gives a helpful error message if the bare role name is a known external principal (advisor, orchestrator, human); it suggests using the `external:` prefix instead (br-a911).
- The CLI is grouped into subcommands (a67t): `bridle daemon`, `agent`, `task`, `usage`, `orchestrator`, `workflow` and a hidden `hook`, e.g. `bridle task claim`, `bridle agent spawn`, `bridle daemon serve`. `status`, `send`, `inbox`, `agents`, `queue`, `events`, `wait`, `tui`, `token`, `port` and `probe` stay at the top level. Every old command line (`bridle claim`, `bridle serve`, `bridle statusline`, ...) keeps working as a hidden alias with identical flags and behaviour; the aliases will be dropped in a later release. Role prompts, rules, skills and `docs/design/cli.md` use the new names.
- `bridle task note` renamed to `bridle task comment` (c7mn): a more intuitive name matching JIRA, GitHub and other tools. The old `task note` command and its flags stay available as a hidden alias. Role prompts, skills, rules and design docs updated.

### Fixed
- `bridle serve --detach` waits 60 s, not 15 s, for the daemon to come up (br-b65b, cy5v); if it is still starting it says so with the pid, log path and `bridle daemons`, leaves it running and exits 0 instead of reporting an error.
- Wall-clock timing assertions in unit tests no longer flake under load (br-7826): moved the 200ms timing assertion in `sweep_uses_one_snapshot_regardless_of_tracked_pid_count` (crates/bridle-daemon/src/containment.rs) behind `#[ignore]` as a load-dependent benchmark, and clarified the ignore reason for `mid_turn_fold_and_interrupt` (crates/bridle-claude/tests/contract_test.rs) to note its 15s timeout is load-dependent. The `parses_fast` test in crates/bridle-spec/tests/spec.rs was already behind `#[ignore]` with an appropriate comment.
- Pane tags are now unique: `bridle pane tag` and session tagging first clear the same tag from all other panes (`tmux list-panes -a`, then `set -u` on others), printing "moved <tag> from <pane>" when it does; failure to list or clear is a warning, never fails the tag itself (br-b6e1, butk gap).
- `bridle task edit --body` keeps a ticket-born task's `original id:` first line (unless the new body has its own), so `ticket check` stays green; its error for a task without that link now names the lost line as a possible cause (br-0e64).
- A named advisor now reads its brief at startup: the opening prompt tells it to check its inbox for "For advisor <name>:" messages and start from the brief when present (jb4e).
- Restart and self-upgrade on Linux no longer exec `<path> (deleted)` after the binary is replaced: the path is resolved once at start-up with the suffix stripped, and a failed exec is logged as an error (fpde).
- Agent PATH construction now uses the pre-resolved `exe_path()` instead of `current_exe()`, so agents always see the correct daemon binary directory even after it is replaced on Linux (fpde follow-up).
- `bridle task done` no longer warns about a missing summary on human-claimed to-dos, since humans don't write task summaries (p4xd).

## [0.4.0] - 2026-09-30

### Added

- The Python pack README documents "Running bridle in CI": a copy-pasteable GitHub Actions step that downloads and installs a pinned bridle release for the runner's platform (Linux x86_64, macOS arm64/x86_64), and the adapter's "cannot run bridle" error references it (wtyn part 2).
- A release workflow: pushing a `v*` tag builds `bridle` for Linux x86_64 and macOS arm64/x86_64 and attaches `bridle-<tag>-<target>.tar.gz` tarballs and `SHA256SUMS` to the GitHub release (wtyn); see Releases in `docs/README.md`.
- The daemon tells the running manager (else the orchestrator) "queue updated: re-read `bridle queue` before you next start something" after the queue settles (30 s trailing-edge debounce); the product manager no longer nudges by hand (f5ww).
- `bridle machine tools-only-install` moves an existing non-bridle `pre-commit`/`pre-push` hook to `<hook>.pre-bridle` instead of refusing, and re-running it once the clone is no longer listed removes bridle's hooks and restores those (ged2).
- The orchestrator (exactly `external:orchestrator`, not a visitor) may edit the queue (`queue set`/`add-tier`) as acting PM on a small project; the PM's planning guidance is now the shared rule `planning-the-queue`.
- Bridle's own tickets now pass `bridle ticket check`: `closed` backfilled on resolved tickets, three invalid ids reminted, dangling `needs`/`see` fixed; the check ignores `[[...]]` inside inline code.
- `bridle ticket set <id> <field> <value>` edits a ticket's frontmatter and `bridle ticket check [--quiet]` verifies every ticket's frontmatter, IDs, `needs`/`see` and `[[links]]` (exit 1 listing problems); new base rule `tickets` and a line in the worker and manager roles (7gk7, slice B).
- `bridle ticket new "<title>"` mints a ticket under `docs/tickets/open/` (fresh ID, frontmatter, matching task when a daemon is up) and `bridle ticket resolve <id>` stamps `closed:` and moves it to `resolved/`; local, works in any project (7gk7, slice A).
- Token counts in `[orchestrator]` config (`note_tokens`, `plan_tokens`, `handover_tokens`) accept an integer or a string like `"150k"` / `"1.5M"`; anything else is an error naming the key. Defaults are 150k/180k/200k (by23).
- Self-upgrade: once a green build waits for a quiet point, new worker spawns are refused (named in the error and in `bridle status`) so running workers drain; lifted if the wait gives up (q7rx).
- `bridle land --checked-commit <sha>`: the landing check is skipped only for a fast-forward whose tip is the commit the worker reported a green check on; otherwise it runs (qgma).

- Focus hours, slice C (br-2e57, cvaq): `mode = "locked"` periods. `bridle focus gate` blocks every prompt ("Locked until 6:00 PM. Email bridle@dev.branam.us if it matters."), `bridle session advisor` and `bridle advisor start` refuse, and the daemon stops all advisor panes from its stall-check loop. The orchestrator keeps running; an active override lifts the lock; nothing changes without `[[focus]]`.
- Focus hours, slice A (br-e540, cvaq): `[[focus]]` periods in `~/.bridle/config.toml` (`days`, `start`, `end`, `mode = "quiet"|"locked"`) and `bridle focus gate`, a `UserPromptSubmit` hook that `bridle session` now passes. In a `quiet` period it adds a "Quiet hours (work) until 6:00 PM ET" nudge on the first prompt and every 5 minutes after. Off entirely without `[[focus]]`; a project opts out with `focus_hours = false`. `locked` parses but does nothing yet.
- Focus hours, slice B (br-ff0d, cvaq): a hand-written `~/.bridle/focus-override.toml` (`until`, capped at 2 hours; `reason`) silences the gate, taking effect `focus_override_delay_minutes` (default 10) after it is written; malformed files are ignored. `bridle status` shows it. Agents are denied `Edit`/`Write` of `~/.bridle/focus*` and `config.toml`. Still off without `[[focus]]`.
### Changed

- With no manager running (`[roles.manager] autostart = false`), the "task filed" note goes to the orchestrator instead of being dropped; the orchestrator role starts a manager on demand and stops it when the project is idle (w2hj).

### Fixed

- The error message when no workspace is found and `--url`/`$BRIDLE_URL` is set now explicitly mentions `--token` as required, so the `bridle --url <daemon url> token create statusline` command's dependency is documented both in cli.md and in the error (br-07b4).
- `crates/bridle-spec/tests/spec.rs::parses_fast` flaked under load because it asserted a wall-clock bound (20 fixture parses under 1 s). Marked `#[ignore]` and run with `cargo nextest run -p bridle-spec --run-ignored only parses_fast`; still catches pathological slowdowns (e.g., quadratic parsing), but no longer fails on a busy machine (k562).
- The `bridle --url <daemon url> token create statusline` command couldn't work without an explicit `--token` flag: `--url` drops the workspace context the human token is normally read from. Documentation now covers both forms (simpler `--project` when the daemon is registered, and `--url --token` for bare URLs), and the discovery error message mentions `--token` (cw7a).

- Disk usage monitor: every `[disk] check_interval` (default 1h, `0s` = off) the daemon logs and records as a `disk.checked` event the volume's free space and the sizes of the clone's `target/`, `wt/` and `.bridle/`, and messages the human once when free space falls under `[disk] min_free_gb` (default 20) (ticket m3wq).

### Changed

- Tasks land as one squash commit each (`git merge --squash`, subject `<task id>: <task title>`, the worker's summary as body, `Task:` and `Branch:` trailers); `bridle rm --delete-branch` now accepts a squash-landed branch, recognised by its `Branch:` trailer (ticket sq4m).
- When a task lands (`bridle task done`), the daemon tells the other running workers that main moved, with the changed files, so they rebase or merge before their next commit; one message per agent per minute (br-07d6).
- A reply from a principal in `[messages] answer_for_human` (default `external:orchestrator`) to a message addressed to the human now closes it: it leaves the unread count and `bridle inbox` and the TUI show "answered by <who>: <first line>"; `Message` gains `answered_by`, `answered_reply` and `answered_line` (ticket h5qd, br-b29c).
- `bridle budget` now shows local-machine times, the applied `five_hour` thresholds with their source (override/schedule period/default), the current period's span, the next schedule change, why the state is what it is, each reading's age (stale by `max_staleness`) and non-`allowed` statuses; `bridle budget --schedule` prints the whole resolved schedule; `GET /v1/budget` gains `five_hour`, `schedule`, `reasons` and `age_secs` (br-75).
- Claude's `allowed_warning` rate-limit status no longer forces wind-down; it is shown by `bridle budget` but the configured thresholds and overrides alone decide the governor state; `rejected` still forces paused (ticket kv7d).
- `just test` (and so `just check`) runs git with an empty global config, like CI, so local runs no longer depend on your `init.defaultBranch` (g3ck, br-d0c3).
- `max_workers` is now enforced at worker spawn (409 at the cap), and `bridle budget max-workers <n>` (`--clear`) changes it live without a restart; after a usage pause, managers, the PM and the orchestrator always resume; the cap limits workers only.
- The human's inbox is for questions, blockers and decisions only; managers no longer send routine status notes; changes are recorded in the changelog.
- Per-project branch pattern: `[branches]` in `.bridle/config.toml` sets the `integration` branch workers branch from and managers merge into (default `main`), and an optional `release` branch no agent but the orchestrator may push; a project trial points `integration` at `bridle-adopt`; `state` is now a reserved agent name.

### Fixed

- `bridle budget --help` (and any `bridle budget` parse) no longer panics on a clap debug assert for a non-existent `conflicts_with = "action"` attribute; added tests for `--help` on budget and related subcommands to catch this class of bug.
- Help text for `bridle statusline`, `bridle prime`, `bridle task` and `bridle usage --by` now accurately reflect their supported roles and options.
- `bridle land` no longer leaves a worktree that has the integration branch checked out (the clone) showing the new tip as staged changes: it fast-forwards there (`merge --ff-only`) instead of `update-ref`, and refuses if that worktree has uncommitted changes (br-land).
- After a budget pause the governor resumes the manager and PM along with workers; `max_workers` limits workers only (ticket k7nr, br-0a50; code landed with y2eb).
- A resumed agent whose Claude Code session is gone no longer dies on its first turn on every resume; the daemon retries once on a fresh session in the same worktree, and `agent.exited` carries the claude `stderr_tail` (ticket p4ks, br-3ec1).
- `bridle renew` no longer waits on a budget hold (it replaces a session rather than adding load), so a hold can't leave the agent stopped; `--ignore-budget` is accepted and ignored on renew (ticket r3nh, br-1392).
- `bridle sync` no longer creates an empty `.claude/settings.json` when there are no hooks to write (br-082f).
- Dropping a claimed task now releases its claim, the claim lease check never moves a task that isn't `claimed`, and the daemon discards claims on non-`claimed` tasks when it loads, so a dropped task no longer lingers under "Claimed" in `bridle queue` (ticket b5br).
- Lists of tasks, edges, claims, open questions, agents and tokens now break `created_at` ties by insertion order, so rows created in the same millisecond no longer come back in either order; fixes a flaky components test (ticket f1ky).
- On Intel Macs (x86_64), `.cargo/config.toml` now ad-hoc code-signs binaries at link time, preventing crashes in macOS's system policy daemon when executing unsigned Mach-O binaries; the flag is a no-op on arm64 (ticket cs7x).
- TUI agents panel and inbox now scroll to keep the selected row visible (tickets yurx, 8ups, br-9e67).
- TUI agents and inbox lists no longer lose the highlight on the selected row (regression from making them scroll) (br-ee7d).
- TUI now shows agents spawned after it started: an event for an agent it has no row for triggers a refetch of the agents list, keeping the selected agent selected (ticket n4vk, br-ee7d).
- `bridle renew` under a budget hold refused only after stopping the agent, leaving it stopped; the hold check now comes first, so a refused renew changes nothing (ticket r3nh).
- An agent renewed and then resumed after a daemon restart before its new session's first turn died on its first turn (`--resume` of a session claude never wrote); `resume` now starts a fresh session in that case (`agents.session_started`, schema v13), and an abnormal claude exit is logged at warn with its stderr tail.
- Autostart now skips a role that already has an agent of that role (any state), not only one named after the role, so a restart no longer spawns a second manager beside e.g. `manager-2` (br-ee7d).
- Daemon shutdown no longer hangs while a client (`bridle tui`, `events --follow`) holds the event stream open; the stream now ends when shutdown begins, and the HTTP drain is bounded at 5s.
